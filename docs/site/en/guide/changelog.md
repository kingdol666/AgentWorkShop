- **v0.9.4 (2026-11-03)** — **Heterogeneous data & MES integration surface completed (H1–H8)**: (1) **MES history → platform TSDB bridge** — agent tool `mes_bridge` + `POST /api/workshop/mes/bridge`: scalar rows go to `daq_samples`, vector/image frames to `daq_frames` (pixels in object storage), tagged by the run window, idempotent on `(node,ts)`, rows outside the batch window carry line tags only, 7-day window / 5000-row caps; `aml_dataset_build` and `aml_node_catalog` now accept mes-rest points, closing the "MES data → dataset → training" chain; (2) **per-node vector grid** — node `driverConfig.resamplePoints`/`sinkOverrides` overrides the template resample, validated at create/patch; (3) **export environment columns** — MES and DAQ exports accept `with_context=true` to append `line_id,run_id,product_id,recipe_id` (off by default to preserve the column contract; manifest/README always carry the environment summary); (4) **supervision-abort decision extracted** into a pure function with unit tests (`abortToCancelDecision`); (5) **MES image frames on the unified retrieval surface** — `mes_fetch` inline images are archived to `daq_frames`/object storage, the frames API accepts mes-rest points (`lineIdOf` real-line permission, thumb requests fall back to the main image); (6) **mes-rest rate/concurrency configurable per origin** — token bucket + concurrency gate keyed by target origin, overridable via node `rateLimitPerSec`/`maxConcurrent`; (7) **DAQ export streaming** — pages are written to disk as they are decoded, memory holds one page; (8) **MES mapping template library** — six templates + `GET/POST /api/workshop/mes/templates`, reducing onboarding from "write three JSON blobs" to "pick a template + fill the endpoint". Acceptance: 1017 unit tests / 1015 pass / 0 fail · lint 0 · typecheck clean · heterogeneous/MES acceptance 23/23 · scientific full-chain 21/21. See `docs/plans/2026-11-03-heterogeneous-mes-plan.md`.

- **v0.9.3 (2026-11-03)** — **Four carry-over findings closed (P2–P5)**: (1) real-line DoE plans are now **step-limit-reachability checked** at creation and before execution — level spacing and the distance from the current value to the nearest level are compared against the effective step limit (node/param/recipe layers, same min-of-layers semantics as the write interlock) and rejected 422 instead of wasting an approval card and line time; the executor now walks a **serpentine feasible order** (monotonic within each control, zero delta at repeat boundaries, seeded interleave across controls keeps de-confounding and satisfies G6's back-and-forth requirement); (2) a successfully parsed vector/image DAQ frame now **clears a stale `lastError`** (same self-healing semantics as the scalar path; warn/alarm remain correct template-band/metric verdicts); (3) when a lead supervision turn is aborted (external cancel / hard timeout), the in-flight task is now auto-closed via an explicit **cancel decision** (reason attached, re-dispatchable) instead of staying WORKING until manual cleanup; (4) **gain estimation trusts only identifiable steps** — new `estimateGainFromRows` excludes underpowered/confounded/negative/zero-delta rows and reports the honest excluded denominator; run results expose `estimatedGain/gainSamples/gainExcludedSteps`. Also: `e2e-hitl-live`/`e2e-auth-matrix` accept `AW_BASE`. Heterogeneous-data & MES REST integration findings plus optimization plan (H1–H8) in `docs/plans/2026-11-03-heterogeneous-mes-plan.md`. Acceptance: 998 unit tests / 996 pass / 0 fail · lint 0 · typecheck clean · scientific full-chain 21/21 · line governance 44/44 · ontology 57/57 · injection closed loop 6/6.

- **v0.9.2 (2026-11-03)** — **Three write-control fixes driven by a live job demo**: (1) the executor waits out the 60s online-write interval before the first real-line step (a freshly started line no longer wastes a whole plan); (2) interval rejections are retried in place with a bounded loop (the interlock still applies — it just no longer fails the plan); (3) **hold-heartbeat vs 60s-interval livelock fixed** — nodes now track `lastChangeAt`, and the interval is based only on *value-changing* writes, so same-value keep-alive heartbeats no longer starve agent/plan writes. Experiment-plan validation also rejects control nodes with `holdIntervalMs` enabled (set it to 0 first). - **v0.9.1 (2026-11-02)** — **Pre-production safety hardening (DoE and dispatch cross-check)**: (1) real-line experiment plans are node-ownership-checked at both creation and execution — cross-line injection, unknown nodes, DAQ targets pointing at DCW nodes, and levels outside the safe range are rejected with 422 (the executor writes as the platform after a single approval, so ownership checks must move forward); (2) **plans can be cancelled while running** (checked before every step, status `cancelled`, ledger rows of executed steps preserved); (3) real-line steps hold ≥60s (same as the write interlock, so step 2 is not rejected with 429 and no line time is wasted); (4) a stale `running` plan is auto-failed after budget+5min; (5) **dual-channel cross-check is wired into dispatch**: when a channel has a bound ARX model, `optimization_explore` rejects in auto mode on a confirmed conflict (model predicts an effect while the ontology explicitly has no coupling path) with a falsification note; unknown never blocks; `AW_CROSSCHECK_GATE=0` is the escape hatch; (6) the intervention verdict is a proper union type (two type leaks fixed).
