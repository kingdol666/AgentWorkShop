# AgentWorkShop 智能体架构创新性与期刊可发表性评估（2026-11-05）

> 范围：Project→Channel「治理式路由编排」模式（proposal-only leader + 确定性调度 + 人工三审批门 + 工业执行面）。
> 立场：诚实区分「真创新 / 工程整合 / 已知模式」；本评估基于公开文献常识，投稿前仍需正式 related-work 检索复核。

## 1. 模式定位（一句话）

**用无 LLM 的确定性路由层（deterministic route）编排有治理封装的 LLM 执行单元（channels），
调度决策与内容生成彻底分离，人只守三道审批门。**

## 2. 与已知多智能体系统的对照

| 系统 | 编排方式 | 与本模式的差异 |
|---|---|---|
| AutoGen / CrewAI | LLM/manager agent 动态委派任务 | 调度即 LLM 决策——不可复现、不可审计；本模式调度器零 LLM |
| LangGraph | 开发者手写状态图 | 图是静态代码；本模式计划由 leader LLM 提案、批准后物化为确定性执行 |
| MetaGPT / ChatDev | SOP 角色流水线（产品→代码→QA） | 角色接力的产出主要供人审；本模式有 attempt/依赖/幂等/审计的账本化执行语义 |
| AFlow / 自适应工作流搜索 | 搜索最优工作流 | 目标是"找好流程"；本模式目标是"治理已批准流程的执行" |
| 工业多智能体（holonic MES 等） | 确定性调度无 LLM | 本模式把 LLM 生成能力嵌入受治理的执行单元，补上"智能"一侧 |

## 3. 创新点分级（诚实）

**A. 有发表价值的真创新（组合层面）**
1. **调度/生成分离的"no-LLM zone"**：调度决策（selectReadyWorkItems：依赖终态∧无在飞∧优先级）被构造性地排除在 LLM 之外，事件 `work.dispatch_auto` 审计可证——现有 LLM-MAS 文献普遍让 LLM 参与调度，这是可检验的差异化主张。
2. **proposal-only leader + 计划版本化批准门**：leader 只提案（plan_version 锁定），owner 批准后按版本确定性执行；"批准的是计划不是代码"的治理语义。
3. **三道人工审批门 + 永不自动完成**：计划/验收/完成三门均有审计与 CAS 决策记录，HITL 不是可选项而是结构。
4. **同一编排面贯通软件开发与工业产线**：工作项既可派发给纯开发频道（落地页自主构建实证），也可派发给绑线频道（DAQ 只读扩权 + DCW 写咽喉分级写穿实证）——LLM 编排与物理产线治理共存的系统证据在文献中罕见。
5. **治理外壳的可复用封装**：工具注册表/策略/执行三态/预算步限/写咽喉，频道可水平扩展（Track D/E 跨频道接力与菱形 DAG 实证）。

**B. 工程整合（有价值但非原创）**
- outbox/双账本/watchdog 是分布式系统标准件（用在 LLM 编排上是加分项不是新发明）；
- 依赖 DAG 调度、幂等键、部分唯一索引并发闸是成熟实践。

**C. 已知模式（不得作为贡献主张）**
- 多智能体协作、角色分工、人在环审批、黑板/信箱消息——均为既有概念。

## 4. 可发表性判定

- **可行路线（推荐）**：**系统/工业信息学期刊**的 Software & Systems 论文——Journal of Systems Architecture、IEEE TII（产业应用论文，与你在投的 TII 改稿生态一致）、Software: Practice and Experience、Journal of Industrial Information Integration。卖点=§3.A 的 1+4 两条（确定性调度主张 + 工业/开发双域实证）。
- **高风险路线**：纯 MAS/ACL 类会议——创新点会被归为"工程组合"，且无算法贡献，大概率被拒。
- **投稿前必须补齐的缺口（按阻断程度排序）**：
  1. **正式 related-work 检索**（2024–2026 LLM-MAS orchestration/governance），逐篇对比确认 no-LLM-scheduler 主张未被抢先；
  2. **定量评估**：至少 2×2（单/多频道 × 简单/菱形 DAG）× N 次重复的派发时延/成功率/回调延迟分布 + 一次端到端 case study（已有 Track B/D/E 可复用为 case study，缺重复与统计）；
  3. **与 LLM-in-the-loop 调度基线对照**（如让 manager agent 动态委派的 AutoGen 式基线），展示可复现性/审计性差异；
  4. 修复审计报告的 P1（派发主链路原子性）——论文声称"治理/可靠"前先消除该窗口；
  5. 安全边界如实声明（Mimosa 扫描 inconclusive；不得写"secure"只可写"audited paths"）。

## 5. 结论

**模式有真实的组合级创新（尤其"调度/生成分离 + 工业/开发同编排面"两条），够到 JSA/TII 级系统论文的门槛，但不是算法突破。**
按 §4 缺口清单补齐定量评估与相关工作检索后，可发表概率：系统类期刊 中~高；顶会主track 低。
