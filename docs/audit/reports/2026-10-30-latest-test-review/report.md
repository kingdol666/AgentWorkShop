# 当前系统最新测试结果评审

**评审日期：** 2026-10-30  
**评审范围：** 最新真实 OMP Channel 验收、最近一次集成基准、最近两次 PIPELINE P12 运行，以及论文现有 R20 证据。此报告审查留存记录，没有重新运行系统测试。

## 结论

最新结果在**已接入能力的广度**上比论文 R20 更宽：同一次 Channel 验收覆盖了数据查询、HITL 写入、自动治理写入、参数台账、AML 查询、求解器门控和本体上下文；但它只覆盖一个模拟工况、一个 OMP Agent 和一条 Modbus-TCP 写路径。R20 则在两个模拟场景中顺序执行六个任务，并逐次关联读回回执与运行标记样本。两者终点不同，不能合并成重复实验或统一通过率。

这批证据**不满足完整 PIPELINE P12，也不足以支持真实设备上线或无缝投产**。最宽的工程覆盖来自确定性集成基准（72/77，5 项警告）；最新的真实 LLM 集成来自单 Agent 模拟任务（24/24）；最近的两次 P12 中，一次未通过运行资格门，另一次资格通过但任务与证据完整性失败。三类结果必须分别报告。

## 集成基准的作业流程与功能覆盖

集成基准 `20261029180436-1lo0` 的测试链按以下顺序展开：

**载入模拟工况与平台 → 建立多协议 Line、Recipe 和 DAQ/DCW 节点 → 采集与驱动读写检查 → Agent 工具闭环（读数—判定—限界写入—读回—复测）→ 配方/回滚/HITL/台账检查 → 多 seed 目标调优 → 切换第二场景检查可移植性 → 越界保护回滚 → Biax 多节点任务 → 汇总报告。**

### 调优结果如何解读

P6 的 Seed 42 从 J=66.454 起步，前两次设定调整后厚度从 55.63 μm 降至 49.85 μm，最终轨迹点为 49.12 μm；Seed 43 首轮 J 从 85.206 降至 77.701，后续恢复到约 88.28，说明过程不是每轮单调改进；Seed 44 的起点已落在厚度、缺陷和压力约束内，0 次写入即停止。P6 支持“特定确定性模拟配置下，治理写路径能完成有界调参与约束检查”，不支持真实材料/设备的优化收益或统计可靠性。

P10 的厚度变化为 28.05→28.00→27.98→24.80 μm，最后落入 24.3–25.7 μm 目标带。三次写入作用于铸片辊速度、快辊速度和出口轨宽；前两步厚度几乎不变，第三步之后出现大幅变化。图中的虚线仅连接离散迭代点以表示顺序，不代表连续采样或独立因果估计。因为它是一次确定性 harness 驱动的顺序模拟任务、并且没有已对账的逐写优化记录链，不能把最终达标外推成一般化的“多 Agent 调参有效”或物理因果结论。

## 与论文实验的关系

论文 R20 在 cast-film 与 annealing 两种模拟场景中顺序运行六个注册 harness 任务，六个任务都完成并有读回回执和 run-tagged 单点采样。六个样本全部低于目标带；采用合成审批和 SQLite 数采回退，单场景的三个任务共用一个模拟器实例，20 s 后的单点不能代表过程轨迹或稳定值。

因此，10 月 30 日 Channel 验收比 R20 **覆盖更多系统模块和治理接口**，而 R20 **覆盖更多任务和两种场景下的任务—回执—样本关联**。新验收不是 R20 的升级重复实验，也没有弥补 R20 的目标未达成、单点采样和模拟器限制。最新 P12 失败/未资格化结果也不能与二者合并成成功率。

## PIPELINE 符合度与上线判断

PIPELINE P12 的完整 episode 要求真实 lead 与至少两名真实 worker 完成平台派发；逐次工具事件具备 Agent、task、tool-call 身份且可与审批、journal、操作记录和独立设备读回对账；数据新鲜度与工况 guard 合格；qualification、workflow outcome、evidence integrity 三项全部 PASS。PIPELINE 还明确规定 P12 是 PLC 数字孪生测试，不代表实体工厂验证。

10 月 30 日 Channel 验收不是 P12 episode：它是单 Agent 测试，且由脚本自动批准 HITL。最近的 P12 一次因 DAQ freshness 未达标而在 goal 前停止，另一次 workflow 与 evidence integrity 失败。因此，当前证据**没有按 PIPELINE 得出完整 AgentTeam 成功结果**。

“按配置接入即可工作”目前得到的是**模拟器中的条件性支持**：在映射与模拟端点相符时，DAQ 读取和 Modbus-TCP 写入/读回可以跑通；集成基准另外覆盖多个模拟协议端点。对真实现场，配置正确是必要条件，但证据没有验证寄存器/地址、数据类型与字节序、缩放/单位、PLC 联锁、权限、安全停机、网络异常恢复、真实采样时延和现场操作员流程。故当前不能判定可直接上线，或“无缝”迁移到真实协议设备。

## 报告可读性与证据修正

原集成基准已有较完整的 Markdown 与 HTML 仪表盘；P12 也提供详细报告和审计文件。最新 Channel 验收只有逐条 JSON 断言，没有专门的可视化流程报告。其摘要便于快速读结果，但“四种协议”计数和 `optimizer_solve` 拒绝原因需按原始断言纠正；脚本把已运行模拟器视为隔离在线，也应在后续报告中降级为环境可用。

本评审随附 HTML 报告、设定值/观测序列图和 CSV 证据表。图中将设备设定值与 PV 观测分开展示，且不连成连续过程曲线；历史观测窗口不足以证明响应的因果关系或收敛。

## 建议用于论文/后续验收的表述

可以谨慎表述为：在所测本地模拟工况和已配置的 Modbus-TCP 映射下，真实 OMP Agent 完成了一次 DAQ 查询及两次受治理设定值写入；脚本模拟批准后，寄存器读回与目标值一致，并产生优化台账记录。其他协议与多场景由确定性集成基准覆盖。当前尚无通过 PIPELINE P12 的多 Agent 完整 episode，也无实体设备投运证据；模拟器观测不能作为生产性能结论。
