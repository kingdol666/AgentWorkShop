### 1.2 事故：:3001 端口双绑定劫持（环境级，已修复）
- **现象**：L1 全环测试第一步登录即失败（AUTH_REQUIRED），且 `node fetch` 与 `curl` 行为**确定性分裂**（curl 成功、node 被拒）。
- **定位**：`netstat` 发现两个进程同时监听 :3001——AgentWorkShop 生产服务器（`scripts/start.mjs`，00:30 启动）与 **IDD 后端孤儿实例**（industrial-deep-diagnostic `src/index.mjs`，前夜 23:49 启动时误带 PORT=3001）。Windows 对 SO_REUSEADDR 冲突绑定的投递不定：node fetch 将 localhost 解析为 `::1`（仅 IDD 绑定了 IPv6 栈）→ 请求全被 IDD 的 Express 401 拦截（`x-powered-by: Express` 是关键指纹）；curl 落到 127.0.0.1 的真服务器。**若不排除，所有 API 级测试结论都不可信。**
- **修复**：taskkill 孤儿实例（30500）；正规 IDD 服务在 :3210 一直健康（插件约定端口）。修复后 node fetch 与 curl 一致，L1 立即恢复 44/44。

## 2. 本轮细节优化（代码改动）

### 2.1 D2 病根修复：save_memory FTS 列过滤注入（P1，野外实锤后修复）
- **野外实锤**：工况A lead 的跨频道冻结约定文档自述 `save_memory 后端故障("no such column: 10")`——与既往轮次取证的 D2 家族吻合，本轮首次在真实作业中再现。
- **病根**（`server/services/workshop/runtime/memory/write.ts`）：共享域近邻治理把 `segmentCJK(标题)` **原文**喂 FTS5 MATCH；标题含 `10:30`/`2026-10-07` 这类片段时，FTS5 把裸 `10` 解析为**列过滤器名** → `no such column: 10`。recall 路径早已用 `buildMatchQuery`（剥 `:+-` + 逐词引号惰性化），写入路径漏用。
- **修复**：`save()` 近邻检索改走 `buildMatchQuery(input.title)`（空查询安全降级为无数组）。
- **回归**：新增 `tests/memory-save-fts-title.test.ts` 3 断言（惰性化器行为 / 带时间戳标题可落库可检索 / 近邻合并语义保留=并存确认标注），3/3 绿；全量单测 174（+3）。

### 2.2 扰动参数语义发现（测试架知识，非代码缺陷）
PLC 模拟器 cast-film 引擎的 `heaterDecay` 被 `clamp(opt, 0.2, 1)` **钳位到 ≤1**——历史上传 1.5/1.8 的"扰动"实际是无效的 1.0。有效扰动必须 `<1`（加热衰减）。本轮据此构造了**可被控制回路修复**的 0.92 扰动（均衡点≈SP×0.92，SP 量程 120~260 内有解）。
