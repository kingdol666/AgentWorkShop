# 真实场景轮报告:PLC 产线闭环优化 + 数据分析 + AML 训练与使用(2026-10-06 凌晨)

> 环境:生产模式 :3001 + PLC 模拟器 :4010(castfilm 物理引擎,castfilm 线)+ MES :15060,全程零系统代码改动。
> 对象:线2「演示线2·熔体泵送单元(OPC UA)」——目标 dn-121838ac(MeltPressure),执行器 dw-38f145fe(ScrewSpeedSP)。
> 结论:**物理闭环全链打通并达标固化**(16.1→15.6 MPa,HITL 全程,审计四连完整);AML 监督模型 **5/5 门禁通过**并晋升 shadow;**模型驱动精确 MPC 被场景级 Twin Gate 正确锁定**(缺 UQ 校准,fail-closed 按设计工作),并定位出数据装配的真实产品缺口。

## 1. 数据获取过程情况

| 项 | 实测 |

| 采样节奏 | dn-121838ac 实测间隔 **中位 2.06s / p90 2.09s / 最大 4.15s**,1 小时窗 1741 行**零断窗**(无丢样) |
| 批次积累 | 线2 累计 **22 个批次**(10-02 起),当前批次 rr-e8fbccff 跨夜连续 |

| 夜间漂移 | 进料漂移扰动下泵压从 15.7 爬至 16.3(1h 内 mean 15.998),构成真实优化需求 |

**发现(G-1,产品缺口)**:数据集构建器的 control 维只能来自数采节点,而线2 的执行器是写控节点(dw-38f145fe)——SP 轨迹只存在于 DCW 写历史,无法进入训练数据集(u 维为 0 维/NaN)。后果见 §4 混合训练;修复方向:构建器支持从 DCW 写历史回放控制序列,或产线加装 SP 回读数采节点。

## 2. 闭环优化控制过程(全链)

时间线(全部有审计/审批单佐证):
1. 00:36 派发 GOAL(泵压 3min 均值 ≤15.8;当前 16.1)→ lead 因跨团队冲突未即时入场(见 3);
2. 00:52-00:58 lead 首轮:六窗基线(16.04/16.00/15.99/16.01/…)→ **自标定斜率 v4=0.107~0.12 MPa/rpm**(与历史 0.134 对照)→ 形成 R1 决策 130→127rpm(-3rpm,量程 2% 步幅上限),预测 15.64~15.68;
3. 00:54 **人工仲裁**:拒绝另一 AML 团队的反向在飞单 ap-06b1cfed(130→133 向上"影子采数",与 GOAL 相向,触发"同配方仅一张在飞单"闸)——恒 HITL 给人类的跨团队仲裁权行使,附书面理由;
4. 其间根任务被 D1 收口一次(reopen 承接 295e4c99;重装配后 6 分钟入场);
5. 01:05:24 `recipe.propose`(R1·130→127·basis=双窗实测+exp_ref 斜率带)→ 01:05:27 `approval.approve`(专家)→ 同秒 `dcw.write.recipe` 127rpm + `recipe.apply`(批次 rr-fcd32e62);
6. 惯性后复测双窗:**15.616 / 15.656 MPa ≤ 15.8**,实测增益 0.127 MPa/rpm(预测带 0.107~0.12,偏差 0.021~0.060,预测可信);
7. 01:12:40 配方**固化 v6@127rpm**(再次 HITL 批准,防回漂);独立复核:泵压 **15.5 MPa**、SP 读回 **127rpm**;
8. 复盘与"隐含斜率 0.127"沉淀频道共享记忆(line2_pump_goal_20261006);GOAL 收口通知送达 AML 团队,承诺错峰共决。

**评价**:这是「观察→提案→HITL→下发→读回→惯性→复测→达标判定→固化→跨团队协调→经验回写」的完整工业闭环,物理侧独立复核吻合;Agent 的斜率自标定与裕度决策(拒绝 -2rpm 的"劣情形烧第二轮")达到产线工程师水准。

## 3. 跨团队执行冲突(真实治理案例)

本轮意外产生一次**多 Agent 团队争用同一执行器**的真实案例:AML 侧历史任务(频道激活时恢复)提交了反向采数提案,占住在飞单闸;闭环 lead 检测→定位对方团队→跨频道协调→等待仲裁而非强行下发;人工仲裁拒绝后让位。平台"同配方一张在飞单 + 恒 HITL"的防抖设计经受了真实考验。(注:恢复即派发的旧任务语义本身是 D1 家族的放大器,已在昨日报告记录。)

## 4. AML 训练与质量

两次监督训练(同数据、同参 epochs=60/hidden=96/lr=1e-3/batch=256,uv 真实环境,mlp_one_step_baseline 契约):

| 门禁 | Run1(split 20%/15%,每侧 1 run) | Run2(split 30%/30%,每侧 2 run) |
|---|---|---|
| G1 单步精度(测试 NRMSE ≤0.1) | 0.0672 ✅ | **0.0559 ✅** |
| G2 滚动精度(horizon=30 ≤0.25) | 0.0671 ✅ | **0.0552 ✅** |
| G3 泛化一致(\|test−val\|/val ≤0.2) | **0.3944 ❌** | **0.0744 ✅** |
| G4 覆盖(≥500 行/≥3 批次) | 15989 行/7 run ✅ | 同左 ✅ |
| G5 工件(契约 ONNX) | ✅ | ✅(46.7KB) |

**训练质量判读**:
- 模型本身质量好:单步 NRMSE 5.6%(≈0.24 MPa 量纲误差的归一化口径),**30 步滚动几乎不衰减**(0.0552)——泵压是慢惯性对象,模型学到了动力学而非噪声;
- **Run1 的 G3 失败是切分抽样伪影,不是模型缺陷**:byRun 切分在 7 run 下每侧只抽 1 个批次,G3 实际在"两个单批次差异"上抽签(val 0.048 vs test 0.067);把每侧扩到 2 个批次后同参重训 G3 即 7.4%。教训入册:**小批次数下 byRun+G3 的方差极大,门禁解读须结合切分结构**;
- 平台复算(authority)与 Agent 自报分离,门禁指标全部来自平台评测器,不可自报——可信。

## 5. 模型使用:治理链按设计锁死

1. `promote candidate→shadow` ✅(附门禁证据备注);
2. 绑定 hybrid_twin 频道 → 409 `AML_BIND_NOT_OPTIMIZATION`(仅 aml_optimization 可绑)✅ 语义正确;
3. 绑定 aml_optimization 频道 → 409 **`AML_MODEL_GATE_REQUIRED`:须先过场景级 `twin_gate_evaluate`**;
4. `twin_gate_evaluate`:G0 行数/批次数、G1/G2/G3 全过,**G4_CALIBRATION_ROWS=0 / G4_COVERAGE ❌** —— 监督模型没有 UQ(不确定性)校准层,**拒绝进入模型驱动 MPC**,fail-closed ✅;
5. 无模型 MPC:`mpc_optimize` → `recommendation-only / safe_small_step`,`modelReady:false, preciseSearchAllowed:false` —— 精确搜索被正确拒绝 ✅。

**双层门禁设计得到活体验证**:训练门禁(G1-G5)≠ 使用门禁(Twin Gate 含 UQ),模型好≠可驱动控制。

**hybrid_residual(UQ 补齐路径)攻坚记录(3 项发现)**:
- 谱系三元组(providerId/Version/Hash)必填,但 **hash 无管理 API 暴露**(最终从 `/aml/twin/providers` 的 provider 记录读到);
- `twin_physics_spec_*` 工具被 profile 闸在 hybrid_twin/aml_training,aml_optimization 频道不可起草——跨频道接力才能走完装配链;
- 提交后训练崩溃 `HYBRID_PHYSICS_NON_FINITE:0:0`(dt=5/1 均复现)——**根因即 §1 的 G-1**:数据集无控制维,物理方程 gain×NaN 第一步即非有限。带控制维重建被 `AML_NODE_MISSING`(角色 control 只认数采节点)拦下。
- 结论:该产线要打通 hybrid/UQ,先补控制维数据(工程改造),不是训练参数问题。

## 6. 缺陷与观察(本轮新增/复现)
- **D1 复现 ×2**:GOAL 任务在等冲突仲裁期间预算烧尽被收口(仲裁→拒绝→解除 HITL 豁免→照常收口的组合拳);承接根两次入场饥饿(重装配解锁)。仲裁-豁免交互是新案例:**人工仲裁行为会意外撤销濒死任务的豁免**。
- **G-1(新,产品缺口)**:数据集构建器控制维不认写控节点/写历史 → hybrid 路线在"只读反馈+写控执行器"的标准产线形态上不可装配。
- **G-2(新,DX)**:providerHash 无管理面暴露;spec 工具 profile 闸使 aml_optimization 频道无法自主走完装配链。
- 观察导出窗 ~1h 收口(G-3),长历史分析需走数据集构建器。

## 7. 结论
- **数据获取**:节奏稳、零丢样、22 批次积累充分;控制维数据缺口是唯一结构性短板。
- **下发控制**:propose→approve→write→apply→readback→复测→固化全链 100% 落审计,物理独立复核吻合;跨团队冲突被治理面消化。
- **模型训练质量**:监督 surrogate 达产线可用精度(单步 5.6%、30 步滚动 5.5%),5/5 门禁;G3 对切分结构敏感的解读已入册。
- **模型使用**:被 Twin Gate 正确锁在 shadow+recommendation-only,**不是失败而是设计**;解锁路径明确(补 UQ 校准数据→hybrid_residual),前置条件是控制维数据改造(G-1)。
