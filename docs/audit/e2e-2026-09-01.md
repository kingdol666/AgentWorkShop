## 2. 本轮直接修复的问题

1. **`limitOf` 丢失致数采表整页白屏**(严重,已修):模板 6 处引用 `limitOf(n)` 但函数定义缺失,
   每行渲染抛 TypeError → 102 行全挂。已补语义实现(活动配方窗口优先,预警带兜底,皆无则不画限值线)。
2. **dev server 被客户端断连击穿**(中,已修):浏览器硬断产生 ECONNRESET unhandledRejection,
   Node v24 默认 throw → 整个 dev server 崩溃,拖垮所有并发调试会话。
   新增 `server/plugins/dev-stability-guard.ts`(仅 dev 生效)捕获记日志。
3. **数采中心卡顿**(严重,已修,前序轮):读数帧 500ms 合批 + `load()` 就地合并 +
   行上下文预计算 + 轮询可见性调度,主线程最长阻塞 1480ms → <100ms。

## 3. 已知问题汇总(未修,按严重度)

### P1-1 Agent worker LLM 回合耗时超观察窗
- 现象:fullchain E2E 中 worker 子任务 WORKING 持续 280s 未完成,HITL 审批未在窗内触发;
  工具调用(invoke 9ms)正常,部署/调度链路完好,脚本清理时 abort 正常。
- 判断:LLM 服务响应时长问题(omp 上游),非平台代码缺陷——同链路 HITL 全环
  (184→178 下发)在历史会话已完整验证。建议:worker system prompt 约束步数 +
  调度器对超时子任务的重派策略(已有 150s supervise 上限,可再评估)。

### P2-1 全站 hydration mismatch(unhead dispose 噪音)
- 现象:每页首载 console 报 `Hydration completed but contains mismatches`;
  特定序列下(同进程先访问 /town 再访问 /)触发 @unhead/vue 卸载钩子
  `undefined.dispose` pageerror。功能不受影响(页面完整渲染、交互正常)。
- 根因方向:SSR 端 store 默认值与客户端持久化值(isDark/locale)首帧不一致。
- 建议:主题/语言偏好改走 cookie 同步 SSR 首帧,或渲染前 `useRequestURL` 判定。

### P2-2 产线 E2E 旧脚本假设过时(非应用缺陷)
- `scripts/_dbg-line-live-e2e.mjs` 假设「单产线活跃」:produced 为全局计数,
  其他活跃产线停线后仍增长(节点级 offline 判定 PASS,停线语义正确);
  脚本另假设配方参数节点恰好绑定在面板展示的设备上(数据演化后不成立)。
- 处置:记录备查,脚本按需再修(不影响任何用户功能)。

### P2-3 双会话共享 dev server 端口拉锯
- 现象:两会话同时 `nuxt dev --port 3000`,后启者自动漂移端口(3002/3100),
  前者停止后造成对端脚本 ECONNREFUSED。
- 缓解:本轮起本会话固定 3100 端口;建议两会话约定各自固定端口。
