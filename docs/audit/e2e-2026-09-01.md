## 2. 本轮直接修复的问题

## 3. 已知问题处置(2026-09-01 二轮修复后状态)

### P1-1 HITL 超时默认拒绝 —— ✅ 已实现并端到端验证
- 机制本已存在(180s → expired → 工具收到拒绝),本轮补齐可见性与可配性:
  - `ToolApproval.expiresAt` 字段(挂起时即确定到期时刻);
  - 审批面板新增倒计时 chip「⏱ Ns 后自动拒绝(超时默认拒绝)」,≤30s 转警示色,轮询 3s→1s;
  - 超时窗可用环境变量 `HITL_TIMEOUT_MS` 调整(产线策略/测试);
  - 超时语义文案对齐:「审批超时未处理,默认拒绝,指令未执行」。
- 端到端验证(`scripts/_dbg-hitl-timeout-e2e.mjs`,HITL_TIMEOUT_MS=5000):
  审批挂起带 expiresAt → 到期自动拒绝 → Agent 工具结果收到
  「指令未执行:用户未在时限内批准(超时)」→ 设定值保持配方目标未被改动 →
  expired 留痕可在 scope=history 查询。ALL PASS。
- 附带说明:worker LLM 回合时长本身是上游模型服务问题,平台侧的
  supervise 上限(150s)+ 审批超时(默认 180s)+ 终态幂等已构成完整收敛链。

### P2-1 全站 hydration mismatch —— ✅ 已修复
- 根因定位(抓取 Vue mismatch 详情):①AppHeader 语言 a-select 的 SSR/客户端
  自动生成 id 不一致(rc_select_TEST_OR_SSR vs rc_select_0);
  ②用户头像/名/角色:session 异步解析,SSR 渲染「?/访客」而客户端已是「张/张伟」。
- 修复:①a-select 显式稳定 `id="hdr-locale"`;②用户身份块包 `<ClientOnly>`
  (SSR 渲染「·」占位,挂载后填充真实身份)。
- 验证:首页加载 hydration mismatch 详情条数 15 → **0**;unhead dispose pageerror 随之消失。

## 4.5 生产模式专项验证(2026-09-01 三轮)

生产构建(`node .output/server/index.mjs`,强会话密钥)下的真值实验,发现并修复 **2 个
被 dev Vite 掩盖的真实 SSR 缺陷**:

1. **首页 SSR 500:`Cannot access 't' before initialization`(严重,已修)**
   `useHead({ title: () => t(...) })` 注册于 `useI18n()` 之前 —— prod SSR 下 unhead
   立即求值函数 title,`t` 尚在 TDZ。dev 下求值时机不同被完全掩盖。
   修复:声明顺序调整 + 全站扫描确认无同类模式。修复后 home 正文 64→1138 字符,0 pageerror。
2. **/workshop SSR 崩溃:`NUXT_E1001 useNuxtApp outside context`(严重,已修)**
   `user store.applyCookie()` 在 `refresh()/login()` 的 **await 之后**调用 `useCookie`,
   请求上下文已丢失;且 SSR 阶段写 Set-Cookie 在响应完成后无实效。
   修复:`import.meta.server` 直接跳过 cookie 写入(登录/登出只发生在客户端)。
   修复前该缺陷可击穿生产进程(护栏 fail-fast 退出);修复后全站扫描全程存活。

**稳定性护栏语义修正**(实现缺陷,已修):初版护栏无差别吞掉 uncaughtException,
把安全插件的 fail-fast(生产密钥校验失败拒绝启动)也吞掉了 —— 服务在不安全状态下继续运行。
重写为严重性过滤:仅抑制 ECONNRESET/EPIPE 等 socket 断连噪声(记日志继续跑),
其余异常记日志后按退出码 1 终止,保留真实错误的 fail-fast 语义。

**生产模式全站扫描(修复后)**:画质三档/自动阶梯 ✅,8 页全部正文完整 + 0 pageerror,
server 全程存活。dev-only 噪音(@unhead dispose pageerror,dev HMR 交互所致)在生产构建下不存在。
