## 2. 过程中发现并修复/调优的治理问题(3 项)

1. **长 HITL 阻塞 vs 根任务 15min 上限**:多轮 DOE(每轮 4min 惯性+慢 LLM)单任务超 `workshop.root_timeout_ms`(默认 15min)→ 整树被 ROOT_TIMEOUT 收口。**调优**:本部署放宽至 60min(重启档)。
2. **回合墙钟硬顶**:supervise 回合硬超时(`supervise_hard_timeout_ms`)对整回合无条件计时 → 30min 时 TURN_STALLED 强拆(实测 09:35:41)。**调优**:20min + 任务指令加「回合纪律」(每轮一个提案-下发动作即收口,跨轮续做)——匹配平台回合制设计。
3. **lead 重建后线2 数采会话断流**(10:16 实测:R3 下发+revert 交错后采样停止;stop/start 线即恢复)——与已修复的 DAQ boot 竞态同族,触发路径不同(回合强拆链),**已记录,待上游根治**。

## 4. 回退语义说明(实测厘清)

- `recipe_rollback(to_last_good)` 需要 **mark-good 冻结过的批次**;无冻结时空回退(诚实无操作)
- `revert {version}` 生成**新版本**(v1→v3 非破坏)但**不自动下发**;下发需显式 apply 或 rollback(dispatch=true)
- 线运行中的 DCW 心跳按**运行时冻结的配方参数**周期重下发——revert 后需 apply 才会改变线上设定(实测:revert 后心跳维持 135,apply v3 后 125)

## 5. 结论

平台「数据获取 → 计划 → 逐参数理由提案 → HITL(快批/慢批/超时三路径) → 下发 → 复测 → 保存 → 版本追溯 → 回退」的完整质量闭环**机制全部在位且行为正确**;长 HITL 阻塞与治理定时器的三方竞态为本轮发现的核心运维议题,已按部署调优并在报告记录上游改进建议(审批等待应暂停根任务时钟/停滞基线)。
