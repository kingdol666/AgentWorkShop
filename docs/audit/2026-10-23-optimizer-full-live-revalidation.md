# Optimizer 计划与真实场景复验

日期：2026-10-23。依据：收敛总计划 v4.1、当前工作区源码、本轮独立实例实测。

**结论：未完整落实，不能将“测试套件通过”解释为“全部计划完成”。** 本轮在本机启动真实应用、Python 求解进程、PLC 物理模拟器和独立 Timescale 数据库。所有设备写入仅限隔离模拟设备，未连接现场硬件。

## 1. 已实证的阻断项

| 计划要求 | 实际结果 | 证据/影响 |
|---|---|---|
| SW2.1–2.2 / MP-A2：配方段边界与版本真实性 | **失败** | 独立 v1→v2 同 run 反例：v2 数据集 131 窗口中 81 个含旧版数据、29 个跨版本，仍标 lineageVerified=1。 |
| 用户自定义训练批次 | **失败** | REST 请求仅 1 个 runId，构建结果包含全部 6 个 run；`dataset.ts` 后续覆盖用户选择。 |
| SW3.4 / DD-A1–2：UQ 独立块及唯一时间点 | **失败** | manifest 校准/测试各 2 块，工件却各记 262 块；272 个唯一测试时间点被记成 1572；错误选用 split_conformal，计划要求 empirical_max。 |
| SW3.1–3.2 / MP-A4：动作证据 | **失败** | 试验、探索和写动作账本均为 0，仍获得 simulation_commanded 与 optimizationEligible=true；真实线仍固定 unknown。 |
| SW3.3 / MP-A4：精确资格 | **失败** | 对应训练数据集报告缺失时回退其他数据集的 latest；查询未完整约束版本、hash、工况和作用域。 |
| SW4：实际模型互校 | **本轮修复** | 同一真实已训练模型原先连续两次 HTTP 500 AML_IO_UNSUPPORTED，修复逻辑变量→采集节点映射后连续两次 HTTP 200/pass。冻结工件未重写。 |

前三类数据/证据错误需要重建数据集、训练及资格，不应通过改测试预期或降低门限处理。

原始反例位于 `evidence/2026-10-23-optimizer-full-live/probes/`。测试脚本分别记录 expected/actual/planPass，失败的计划断言不计入通过。

## 2. 尚未完成的系统能力

- SW1 统一授权/拒绝审计尚非全入口统一：`solve.post.ts` 仍经基础成员检查直接调用 manager；若干 binding/run 分支的拒绝未汇入统一审计。完整 17 handler 与批准时八项负例仍须补证，不能以部分跨用户单测代替。
- 模拟试验只有计划/状态 CRUD，没有调度→治理写入→回读→保持采集→归档的持久执行器，也没有对应完整 UI。
- 单长 run 的 purge 切分、静态稳定段筛选、Timescale 到达/状态/迟到/分页语义没有完整实现。
- 跨进程环境读租约、完整依赖锁、真正 SolverAdapter 路由、按 solverRef 的 Worker v2、发布时服务端冻结 IR、多工况 hash、MD 成组支持仍不满足 SW6。
- 三个公共 typed predictor 调用入口的工程/模型单位转换尚需逐项补齐；本轮逻辑 ID 修复不宣称解决单位契约。
- 原计划要求的两场景 40 配对收益基准、第三留出场景配置全链、刷新时序与回滚演练，不能由合成 ARX 的单条收益轨迹代替。

## 3. 本轮测试与修复边界

本轮局部产品修复仅为 typed predictor 的 ID 映射与返回节点契约；新增真实训练/注册回归。另完善测试隔离、证据目录与请求目标参数，去除收益测试对求解结果的事后限幅，避免测试掩盖约束违反。

基础回归首轮：TypeScript 412/412、Python 回归 6/6、数值矩阵 34/34；完整 typecheck、双语和文档检查通过。新增修复后的最终结果、生产构建、浏览器、重启、PLC 物理场景结果以本报告后续记录与 `summary.json` 为准。

首轮开发实例浏览器测试保留了失败记录：测试账号姓名硬编码不适用于复用账号；开发服务热更新期间出现连接重置及后续导航超时。生产实例复跑将独立记录，不删除首轮失败。
