### 审批点击阻塞分析(诚实记录)

四个途径依次尝试并全部记录:①computer-use 真实 Edge(初期成功:导航/截图/AX 观察;后助手降级 response-lost);②全旅程脚本(认证/仪表盘/产线过,重 DOM 扫描挂死);③聚焦脚本(登录+卡可见性解决;批准求值超时);④铃路径(下拉内项目未现=store 轮询时序)+CDP 点击(同样超时)。
**根因定位**:测试环境累积 14 个僵尸 headless Edge 进程(其一 CPU 空转 1673 秒)重压宿主 + 重载页面在 headless 下的 WS 重连风暴(2.6 万条控制台错误)使页面主线程卡死——**是自动化测试环境的阻塞,不是 UI 本身缺陷**;僵尸进程清理后页面求值恢复响应(铃诊断 evaluate 秒回)。

## 四、本轮新发现(测试环境级,非阻断)

1. **生产限流真实有效**:默认姿态 429 拦截高密度测试(投用后对真实用户是保护;测试机按配方关限流)。
2. **待批审批卡不跨重启**(内存态):平台重启后 pending 卡消失——fail-safe 方向(丢失而非误批),但生产 SOP 应写明"重启前清审批队列"。
3. **HITL hold 模式可用**:PATCH /api/system/settings {'security.hitl_timeout_mode':'hold'} 后新卡无过期(本轮实测);reject 缺省 2h 窗。
4. **在飞单去重**:同配方已有待批卡时新提案返回既有卡号(防重复提案)。
5. 前端 Hydration mismatch ×8(已知非致命瑕疵,不影响功能)。
