# 数据获取/下发 权限隔离审计报告(2026-10-10)

> 用户命题:①Agent 只能获取自己绑定节点的数据(DB 与 MES API 两路);②优先获取当前 recipe 的数据,非当前 recipe 不优先但节点数据仍可获取;③recipe/产品/产线节点隔离;④未绑定节点数据库不可获取;⑤下发仅限绑定 recipe。

**用户所述语义与系统实现完全一致,且全部经真实阴性/阳性测试实证(8 项测试 0 放行)。** 代码判定点集中、无旁路。

## 四、语义边界(如实说明)

1. **"recipe 优先"是查询口径语义**(打标过滤),不是访问控制 —— 访问控制始终=节点绑定;两者正交。
2. 打标粒度到 **recipe id**(版本迭代同一 id 不切分;跨 recipe id 精确切批,T8 实证)。
3. 产品隔离与 recipe 同机制(product_id 打标过滤 + 默认活动批次携带 productId);节点唯一归属产线,产线隔离经由"节点绑定 ⊂ 产线"实现。
4. mes-rest 历史专节点的可见面授权 = 授权配方模式(2026-10-10 实测定稿,kind='dcw' 直绑已废弃)。

## 五、判定

**隔离模型完整:绑定即边界、活动批次即默认口径、打标即精确切批、未绑定即不可见 —— DB 与 MES 两路、读与写两面一致。**
