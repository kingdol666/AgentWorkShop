# PROTO 文档驱动虚拟验证 — 产线接口说明书

> 用途:作为 `aw-protocol-onboarding` 的输入文档,由 Agent 提取点位、生成 `blueprint.json` 与供给配置,在虚拟设备上完成采集/下发/分析/导出验证。本文是虚拟设备合同,不是真实厂家文档。

## 1. 产线

- 名称:`PROTO-文档驱动虚拟线-1031`
- 场景:涂布/箱体温度 + 壁厚轮廓 + 环境温湿度
- 设备端:本机虚拟 HTTP 设备 `127.0.0.1:4020`;MQTT broker `127.0.0.1:18830`
- 认证:无(loopback 虚拟验证)

## 2. 点位表

| 点位 | 方向 | 协议 | 地址/主题 | 取值 | 单位 | 量程 | 周期 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 箱体温度 PV | 只读 | HTTP | `GET http://127.0.0.1:4020/pv` | `value` | ℃ | 10–60 | 2s | 24.5–25.5 正弦 |
| 箱体温度 SP | 可写 | HTTP | `POST http://127.0.0.1:4020/sp` | body `{"setpoint": <value>}` | ℃ | 10–60 | 手动 | 单步 ≤2℃;无保写心跳 |
| SP 回读 | 只读 | HTTP | `GET http://127.0.0.1:4020/sp` | `setpoint` | ℃ | 10–60 | 2s | 用于独立证实下发 |
| 壁厚轮廓 | 只读 | HTTP | `GET http://127.0.0.1:4020/profile` | `points[64]` | mm | 1–5 | 5s | 向量,64 点 |
| 环境温度 | 只读 | MQTT | `aw/proto/doc/env` | `data.temp` | ℃ | 0–50 | 1s | 与湿度同报文 |
| 环境湿度 | 只读 | MQTT | `aw/proto/doc/env` | `data.humidity` | % | 0–100 | 1s | 与温度同报文 |

## 3. 报文样例

HTTP `/pv`:

```json
{ "value": 25.13, "ts": 1793380000000 }
```

HTTP `/profile`:

```json
{ "points": [2.501, 2.503, 2.498, "… 共 64 点"], "ts": 1793380000000 }
```

MQTT `aw/proto/doc/env`:

```json
{ "ts": 1793380000000, "data": { "temp": 22.4, "humidity": 55.2 } }
```

## 4. 控制约束

- SP 执行点:箱体温度设定;量程 10–60℃;单步 ≤2℃;首次接入 manual,不得直接 auto。
- 写后必须用独立 DAQ 回读点(`GET /sp`)证实物理跟随;HTTP 写驱动只给 `transport-ack`,不能冒充设备证实。
- 环境温湿度共用同一 topic;两个字段分别建节点,不要求单节点多列。
- 壁厚轮廓是向量,不是标量;不要用 `daq_query` 的标量样本接口判读,应查 `/frames` 或导出 `frames/*.csv`。

## 5. 验收判据

1. 6 个点位全部有真实样本/帧:PV、SP 回读、壁厚 64 点、环境温度、环境湿度。
2. 写 SP=27 后,SP 回读 DAQ 在 5s 内变为 27;写回 25 后恢复。
3. 壁厚向量每帧 64 点,metrics avg/max 在 1–5mm 内。
4. 导出 CSV 行数/列名/值域与 manifest 一致;向量长表 64×帧数。
5. 不修改既有产线/节点/配方/频道;只创建 `PROTO-文档驱动-*` 资源。
