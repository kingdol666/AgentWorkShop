## 1. DOE 闭环寻优(目标驱动,真实物理)

### 1.1 实验设计
- **GOAL**:dn-0183240d(熔体温度,modbus)3 分钟窗均值 ≥ 200.8℃;护栏:测厚 ≥ 78μm
- **因子**:加热区1SP(窗口 120~260,单步 ≤5);MES 泵速恒 55(单变量隔离)
- **方法**:梯度试探——每轮 recipe_propose 提案 → HITL 批准 → 下发 → 等 4 分钟惯性(tauZone=90s×3 区 + tauMelt=20s)→ daq_query 复测 → 按斜率外推
- **裁决者**:userA(频道成员,线A operate 授权)经 `/hitl/respond` 应答——**非 admin 的群聊 HITL 协同实证**

### 1.3 Agent 的科学结论(残差分析,原文要点)
> 实测有效增益 ≈0.03~0.05℃/℃,否定「扣除漂移后 +1℃/℃」的人工假设;五点单调梯度否定了「进料温漂 ±6℃」单独解释;**最可能机理:该工况点 zone1-SP→熔体温度耦合≈0**(区1 热贡献被邻区/剪切热主导);继续单调加码无法达标(窗口上限余量已算尽)。

R4 判定窗用「剩余桶全取全程峰值」的上限法做数学锁定(≤200.57 < 200.8),拒绝凭不完整窗口下结论。
**收尾治理**:尝试 recipe_rollback(该配方无 mark-good 冻结批次 → 诚实空回退),最终由 admin 经 REST 恢复基线 193℃(批次 rr-ff2e9bf7)。

## 3. 公开群聊 + 群聊 HITL 协同 + 海龟汤

- **搭建**:admin 建公开绑线A频道(public+chat_enabled+open)→ userA/userD 加入 ✓,userB/userC 被产线闸拒绝 ✓
- **@worker 真实回复**:omp worker 报到并自述工业职责(产线全景/数采与 MES 数据/参数寻优与配方试验)
- **HITL 协同**:ask 工具未挂载时 worker **诚实降级**为群聊提问并逐级上报(不伪造工具结果);任务内 HITL 由成员(userA)裁决成功、重复应答被拒
- **海龟汤**(worker 主持,经典「要水/拿枪」谜面):
  - Q1「男人中枪了吗?」→ **不是** ✓
  - Q2「他和酒保之前认识吗?」→ **不是** ✓
  - Q3「酒保拿枪是想帮他吗?」→ **是** ✓(worker 还先核查频道名册决定回复路由)
  - userA 猜底(打嗝+惊吓疗法)→ worker 确认「**完全正确🎉**」并公布完整汤底
  - 全程 3 问 1 底,每轮 LLM 回复 1~2 分钟,群聊顺序与归属无错乱
