# 5 分钟演练清单（oncall-drill）

**用途**：接班后 30 分钟内完成一次 5 分钟演练，验证当班值班员能否在真实读数上跑通「巡检 → 分诊 → 升级 → 回滚就绪 → 交接」全链路。演练默认只读，桌面推演为主；任何参数下发、停线、配方回滚在演练中一律标注「模拟」，不产生真实写操作。

**前置**：line_status、line_context、ops_log、recipe_versions 四类读数可打开；告警渠道与当班负责人电话可用；演练记录表已就位。主导人：当班值班员；旁听与计时：接班人。

## 一、0:00–5:00 演练步骤

| 时间窗 | 动作 | 观察 | 通过标准 |
| --- | --- | --- | --- |
| 0:00–0:40 | 调 line_status 与 line_context，口述活动批次号、执行配方名与版本、PLC 当前参数条数 | 时间戳是否为当前、批次是否唯一、配方是否处于活动态 | 40 秒内报出批次/配方/参数条数三项，与平台实时读数逐项一致；缺任一项记「不通过」，按 P2 转排查 |
| 0:40–1:40 | 读 ops_log 近 30 分钟与本班巡检记录，指出最近一次下发、回退与告警 | 是否有未闭环告警、下发是否有回读证实 | 能点名最近 1 条下发（时间+操作者+回读结论）与全部未闭环告警；漏报即不通过 |
| 1:40–2:40 | 接收演练注入单（示例：配方某参数目标值与 PLC 当前值偏差 1 项），按手册定级并给出分流对象 | 定级是否落在 P1/P2/P3，通知对象与时限是否匹配 | 2 分钟内给出级别、通知对象、时限三项，且与手册条款一致；级别说错即不通过，不得事后改口 |
| 2:40–3:40 | 按级别执行升级：口述通知对象、渠道与话术，记录发出时间；同时声明「本演练不下发、不代签」 | 升级是否在时限内发出、是否越权承诺 | 升级话术含现象、影响、已采取措施、需要对方做什么；P1 在 5 分钟内、P2 在 15 分钟内发出；出现代签或承诺即判不通过 |
| 3:40–4:30 | 做回滚就绪核验：查 recipe_versions 指出可用 lastGood 版本、回滚工具与回读方式，说明回滚影响面 | 版本是否存在、审批链是否可用、回读是否可执行 | 能报出版本号、目标参数 diff 条数、回读核对点三项；任一不可达记「回滚不就绪」，演练结束前升级 P2 |
| 4:30–5:00 | 填演练记录表与交接单，向接班人做一句话交接并取得确认 | 记录字段是否完整、接班人是否复述确认 | 记录表五项齐全（时间/批次/注入项/结论/责任人），接班人复述确认后方可结束 |

计时规则：任一步超时即记录实际耗时，不中止演练；整轮超过 5 分钟记「超时」，由接班人写入交接单，下一班复训一次。

## 二、回滚步骤

回滚只在确认参数或批次异常已造成质量风险时执行，且必须由授权执行者按审批流程操作，值班岗负责取证、申请与回读核对，不直接写设备。

1. **触发条件**：配方目标值与 PLC 读回不一致且已影响在制产品；或错误参数已下发、批次窗口出现交叉。
2. **回滚前取证**：冻结当前批次窗口，导出 ops_log 与参数快照，记录异常发生时间、涉及参数、影响批号；未取证不得回滚。
3. **参数级回滚（路径 A）**：在 recipe_versions 选定最近已知良好版本，申请 write_intent（tool 与 args 固定为 recipe_rollback + 配方 id + 版本号），owner 批准后下发；批准只对同参数同目标的一次调用有效，改参数须重新申请。
4. **批次级回滚（路径 B）**：先 line_stop 关闭当前批次窗口并写明原因，再按路径 A 恢复配方并重新开线；禁止在活动批次内边跑边改。
5. **回读判定**：下发后逐参数回读 PLC 当前值，三项全过才算完成——参数逐项一致、活动批次唯一、打标样本连续且无跨批次。
6. **回滚失败**：回读仍不一致或指标继续恶化，立即停线冻结、升级 P1、保全现场，不做第二次盲目回滚。
7. **时限**：参数级 10 分钟内完成，批次级 20 分钟内完成；超时升级。演练中只核验第 3–5 步的版本、审批链与回读手段是否可达，不执行真实回滚。

## 三、交接记录

演练结束即填写，随班次交接单归档：

| 字段 | 填写要求 |
| --- | --- |
| 演练时间 | 起止时刻，精确到分钟，注明班次 |
| 产线读数 | 活动批次号、执行配方名与版本 |
| 注入项 | 演练注入的异常描述与定级 |
| 各步结果 | 六步逐项写通过/不通过/超时，附实际耗时 |
| 回滚就绪 | lastGood 版本号、审批链与回读手段是否可用 |
| 遗留事项 | 未闭环项、责任人、截止时间、判定标准 |
| 双确认 | 主导人与接班人签名及确认时间 |

交接要求：口头说明加书面记录双确认，接班人复述关键结论后方可交班；演练不通过的项在两班内复训，连续两次不通过升级 P2 并书面报 owner。交接记录只写事实与读数，不写推测；读数与现场不一致时以平台实时读数为准并同时登记现场口径。
