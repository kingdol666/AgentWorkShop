02 / 能力

产线不缺聊天框， 缺一层能负责的执行。

六个工程问题，六个能落到界面与代码里的答案：谁来做、怎么读、写什么、谁批准、如何验证、出错怎么办。

01 / TEAM

团队，而不是单机对话

lead 拆解目标，worker 交付结果；7 态任务机、FIFO 根队列、租约 fencing，防止同一目标被重复执行。频道内消息、共享记忆与定时任务同属一个运行时。

14 引擎混编7 态任务机FTS5 + 向量记忆
02 / FIELD

现场，而不是接口清单

Modbus TCP/RTU、OPC UA、MQTT、HTTP 直接接入，串口插件接入串口设备；MES REST 支持镜像与直连。数采按节点独立节奏运行，断面与相机帧统一入库。

5 类内置协议串口插件MES 镜像/直连
03 / WRITE

写入，默认不放权

直接写节点在工具面已被禁用；参数写入只走绑定配方。点位/配方/全线配方三轨授权，叠加四层限幅、单步上限、运行门与 60 秒联锁，任何一层不通过就不下发。

三轨授权四层限幅60s 联锁
04 / HITL

审批，是链路的一等公民

manual 绑定下，每次下发挂起等待人工批准；审批卡展示提案、依据与限幅结果；180 秒无响应按拒绝收敛，指令不执行、不产生下发。

HITL180s 超时拒绝审批留痕
05 / ROLLBACK

回退，不抹掉历史

配方版本化，支持候选试验与整批下发、逐参数 ACK；回退生成新版本而不是覆盖历史，可整批恢复 PLC 参数。每一次变更都能回答“谁、何时、从多少到多少、为什么”。

非破坏回滚逐参数 ACK版本链
06 / MODEL

模型，也要过门禁

AML 用物理先验 + 残差集成 + conformal 不确定度建模；从影子观测到生产生效需人工采纳；工艺优化器按“建模 → 求解 → 试验 → 仅在提升时转正”运行。

shadow → productionconformal UQOSQP

再往下还有：本体服务与规则编译 · 3D 数字孪生 · 插件热重载（驱动/处理器/工具/面板） · WS / MCP / A2A / REST 四入口 · 定时任务与运行监控。

03 / 闭环

一条闭环， 六个可检查的动作。

从 5 分钟真实时序开始，到一条可复盘的台账结束。每一步都能在界面上找到证据，而不是只出现在 PPT 里。

01绑定｜让 Agent 先懂设备

语义卡随绑定注入：物理量、单位、安全量程、配方窗口与调参守则。Agent 不需要猜 “182” 代表什么，也不会把温度当成压力。

证据：绑定详情中的语义卡与授权轨道（读 / 配方面写）

02读数｜只拿真实数据

daq_query 返回带统计与采样窗口的时序；MES 历史可按批次桥接进同一时序库；向量断面与 CCD 帧同库可查。Agent 的回答必须能指回采样点。

证据：查询窗口、采样点数、统计值

03提案｜先算，再说

在配方面上给候选参数，逐项附 basis 与经验引用；超出限幅的提案在生成阶段就被拒绝，不会等到写入才失败。

证据：参数 diff、依据文本、经验引用

04审批｜人来签字

manual 绑定下每次下发挂起；审批卡展示提案、依据、互锁结果与操作者；180 秒无响应按拒绝收敛，不产生任何下发。

证据：审批单、操作者、时间戳、裁决结果

05写入｜四层收窄，回读为准

安全量程 ∩ 参数基准 ∩ 产品限界 ∩ 配方窗口逐层收窄，再经运行门与 60 秒联锁；PLC 写入后回读校验，逐参数 ACK。回读不一致即判失败，如实回报并记入错误账本。

证据：互锁结果、回读值、ACK 码

06入账｜让下一次更好

写控与配方台账、错误账本、/operations 时间线记录全过程；回退生成新版本，历史可追溯。下一次提案可以直接引用这次结论。

证据：台账条目、版本链、错误归因
默认建议，不默认放权。

平台的默认姿态是 advisory：写入必须过人、过锁、过回读；产线侧逻辑始终拥有最终否决权。Agent 的能力上限，由你的绑定与审批配置决定，而不是由模型心情决定。

04 / 架构

AI 控制面 × 工业数据面， 共用一套状态。

不是把模型接在 SCADA 旁边，而是让团队、任务、权限、配方、时序与事件共享同一个运行时和同一份审计。

读 / READ

语义卡→数采网关→时序库→Agent 上下文

每个节点独立采集；历史、统计、向量断面、图像帧走同一查询面。

写 / WRITE

提案→限幅 ∩ 联锁→人工审批→PLC 写→回读→台账

写入是唯一咽喉点，四层限幅与审批不可绕过。

事件 / EVENTS

采集 · 写入 · 审批→事件总线（per-channel seq）→WS/AEP→3D 孪生与大屏

断线可按 seq 续传；每个频道的事件顺序可复核。

05 / 部署

两分钟启动， 从一个可回退的工位开始。

不必先换 PLC，也不必先把数据送上云。私有化内网部署，模型引擎按你的环境选。

INSTALL
$ npm install -g agentworkshop
$ aw start
# → http://localhost:3001
OPTIONAL INFRA
$ docker compose up -d   # MQTT · TimescaleDB · MinIO（可选）

Node ≥ 23.4（内置 node:sqlite）· 配置优先级 config.yml < runtime-settings.json < 环境变量/CLI · Apache 2.0 商用许可 · 数据全部落在配置根目录并随版本迁移

  1. 选一个可回退的工位：温控、张力或厚度，最好有 5 分钟以上历史数据。
  2. 接一个读点、一个写点：建线、建产品与配方，先不接 Agent。
  3. 绑定 manual：给 Agent 读数权限与配方面写权限，所有下发等人工批准。
  4. 跑一次诊断：用真实历史时序生成一份带依据的提案。
  5. 审一次、回看一次：批准或驳回，检查回读值与台账，再决定是否扩大范围。
Agent 能直接写 PLC 吗？

不能。直接写节点在工具面已被禁用；参数写入一律走绑定配方，并同时受三轨授权、四层限幅、运行门、60 秒联锁与人工审批约束。

审批人不在会怎样？

manual 绑定下写入挂起等待；超过 180 秒按拒绝收敛，指令不执行、不产生下发，Agent 会收到原因。

支持哪些设备与系统？

Modbus TCP/RTU、OPC UA、MQTT、HTTP，串口插件可补 RTU；MES 走 REST（镜像或直连）。协议驱动与节点模板可通过插件扩展。

断网或设备掉线怎么办？

真机矩阵包含“诚实断连失败”与自愈用例；写入必须回读一致才算成功，失败会如实回报并进入错误账本。

必须用公有云大模型吗？

不必。harness 是适配层，14 个引擎可按通道混编；mock 可进程内运行，其他引擎按 CLI 或模型端点配置。

数据存在哪？能私有化吗？

默认 SQLite（node:sqlite），可选 TimescaleDB；所有数据在配置根目录并随版本迁移，整套系统可部署在内网。

许可与商用？

Apache 2.0，允许商用与生产使用。上真机前请先复核互锁、安全量程与 HITL 配置；默认姿态是建议性，产线侧逻辑保留最终否决权。

把第一个工位，变成可验收的闭环。

不需要一场 PoC 演讲。带上一条产线的历史数据，我们用你的工况跑一遍「读 → 算 → 批 → 写 → 回读」。
