# 四种绑定方式 × 真实协议验收(line-recipe / recipe / dcw / 无 dcw)

- 日期:2026-10-29
- 结论:**19/19 PASS**。四种绑定方式的允许/拒绝与设备侧实际变化完全一致：
  - 窄绑 dcw + 配方 → 下发**收窄**到绑定点位，未绑点被拒并点名；
  - 仅配方绑定（无 dcw）→ **向下兼容**，整配方全参数可下发；
  - 产线管理权（line-recipe，无 dcw）→ 可新建/修改配方，且全参数可下发；
  - 无任何绑定（仅频道绑线只读）→ 读允许，写/版本操作拒绝。

## 一、场景

一条真实 Modbus/OPC UA/MQTT/HTTP 产线（物理孪生模拟器），配方 R1 含 4 个参数（加热区1 设定 / 螺杆转速 / 线速度 / 模口间隙）。四个独立频道绑定同一产线，分别给 Agent 不同绑定：

| Agent | 绑定 | 频道模式 |
|---|---|---|
| A 窄绑 | dcw(加热区1, 螺杆) + recipe(R1) | manual(HITL) |
| B 仅配方 | recipe(R1) | manual |
| C 产线管理 | line-recipe(整线) | manual |
| D 无绑定 | 无（仅频道绑线） | manual |

所有写操作走真实 `agent-tools/invoke`（Agent 令牌 + HITL 人工批准），设备侧读模拟器信号值。

## 二、结果

| # | 断言 | 证据 |

| C1 | 产线管理权可新建配方 | 新配方 `rc-e85813cb`（无需单配方绑定） |

## 三、结论与边界

1. **绑定语义与设计一致**：dcw 是点位写授权，有 dcw 时下发按点位收窄；无 dcw 时配方级授权（recipe/line-recipe）即全量放行 —— 这正是 2026-10-28 裁定的“向下兼容 + 收窄”双规则。
2. **管理权与下发权分离**：line-recipe 可新建/改/回退配方；是否收窄只取决于是否存在 dcw 绑定。
3. **读面独立**：即使无任何 Agent 绑定，频道绑线仍提供只读数据面（D3）。
4. **模型环节说明**：本套件只用 Agent 令牌 + HITL 验证授权契约（确定性）。Qwen 实时抓数已在 `2026-10-29-mes-mirror` Q1 覆盖；模型自主下发已在 `2026-10-28-physical-effect` 覆盖。本地 9B 在长工具任务回合会偶发长时间不产出，放进授权门禁会把结论变成模型可用性抽奖，故不纳入本套件。
