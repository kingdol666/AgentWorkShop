# Huashu Design · 全局风格三方向

项目：AgentWorkShop Web + Electron 共用页面
媒介：生产级 Dashboard / desktop workspace 视觉原型
现有上下文：`app/assets/css/main.css`、`app/app.vue`、`desktop/chrome/splash.html`

## 共同内容与约束

- 观众：产线工程师、Agent/Project 操作者、需要审阅证据的负责人。
- 任务：三秒内知道“现在是否健康、哪件事需要关注、下一步安全动作是什么”。
- 视觉温度：冷静、精确、有一点工具感；不做营销页。
- 主色事实源：signal green `#35e0a0`；语义色仍然只表示真实状态。
- 真实内容：运行产线、采集、告警、Agent 会话、任务进度、审批与证据。
- 交互：页面载入有一次编排好的进入；状态变化用短促的 transform/opacity；高频导航不做过度动效。
- 移动：不把桌面多列缩小，而是重排为单列 + 抽屉 / bottom dock。

## 方向 1 · Signal Deck / 信号甲板

**逻辑与来源**：最佳设计师候选为工业仪表界面 / 信息可视化工作室；现实机制借同媒介的航空/工业控制台：状态栏固定、主图表占据中央、告警按优先级进入侧带。不借其军用色彩与密集按钮表达。

**借的机制**：一块连续的中央数据平面，用一条可读的时间趋势线承载“系统正在工作”的证据；关键状态不拆成 12 张同样的卡。

**不借的表达**：不做雷达绿、黑黄警戒条或模拟仪表盘仿制；颜色从 AgentWorkShop 的 signal green 与冷钢灰长出来，字体沿用 Geist/Geist Mono。

**主角素材**：程序化数据图像——实时工况趋势、节点状态带、告警脉冲。

**骨架**：左侧固定导航 → 顶部健康条 → 中央大趋势 + 右侧告警堆栈 → 底部任务轨。

**胆量**：让趋势图成为一整块“工作台面”，指标只在图周围做刻度，不把每个数塞进卡片。

**form 来自内容的哪里**：产线数据本来就是连续的时间流，而不是一组孤立的营销指标。

## 方向 2 · Operations Ledger / 运营账页

**逻辑与来源**：最佳设计师候选为信息编辑 / 现代报表工作室；现实机制借项目管理产品的“今日简报 + 证据清单”，让页面先给叙事，再给结构化数据。不借报纸头版装饰与大面积衬线。

**借的机制**：按“现在 / 接下来 / 已完成”组织同一工作流，给项目负责人一个阅读顺序，而不是先扔一墙图表。

**不借的表达**：不使用纸张仿真、编号装饰或暖奶油模板；浅色仍然使用冷纸背景，Geist 为主，衬线只做极少的品牌注释。

**主角素材**：真实任务证据——审批节点、最近事件、交付完成度和可追溯时间线。

**骨架**：轻量左栏 → 大标题与今日判断 → 主叙事栏 → 右侧“下一步”清单 → 底部证据表。

**胆量**：用一条纵向“证据线”把状态、动作和时间串起来；数据表只是证据，不是首屏主角。

**form 来自内容的哪里**：Project / Agent 工作本质是“目标到证据”的过程，阅读路径比指标数量更重要。

## 方向 3 · Twin Stage / 孪生舞台

**逻辑与来源**：最佳设计师候选为数字孪生 / 空间 UI 工作室；现实机制借 CAD/节点编辑器的“中央对象 + 环绕上下文”，让 Channel、Agent、设备与任务成为可定位对象。不借 3D 科幻 HUD、霓虹光晕和全屏玻璃。

**借的机制**：中央空间只保留一个当前对象；左侧是关系入口，右侧是动作和证据，避免三栏都同时争夺注意力。

**不借的表达**：不做赛博朋克、不做漂浮卡片墙；以实心冷表面、细线关系、信号绿单点作为产品自己的表达。

**主角素材**：程序化关系图——当前 Channel 与 Agent/Task/Line 的关系节点，以及可展开的状态轨迹。

**骨架**：左侧对象索引 → 中央孪生舞台 → 右侧上下文抽屉 → 底部 command dock。

**胆量**：中央对象状态会轻微呼吸，关系线只在选中对象时出现；空间留白本身表示“还没有证据”。

**form 来自内容的哪里**：系统不是单纯聊天，也不是单纯监控，而是 Agent、Channel、Session、Task 和产线对象共同组成的运行关系。

## 六个未入选候选

- “Strict Monochrome”——只用黑白和一支绿，过于接近现有 Industrial Instrument，不足以形成独立方向。
- “Paper Archive”——用档案夹/纸张作为隐喻，容易把治理界面做成道具。
- “Terminal Bloom”——强调终端流和日志，适合 monitor 但不适合全站。
- “Soft Twin”——用暖色柔和玻璃表现孪生，和工业控制的风险语义冲突。
- “Metric Wall”——把所有页面都变成指标墙，失去 Project/Conversation 的阅读性。
- “Orbit Map”——关系节点做成轨道图，空间感强但容易遮住真实数据。
