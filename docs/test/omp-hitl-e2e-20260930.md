# omp 真引擎闭环端到端实测:配方链路 × HITL 人机卡控(2026-09-30)

- 实例:127.0.0.1:3990(隔离配置根,`AW_MODE=home`;`AW_TRIAL_INTERVAL_MS=8000`;`security.recipeDispatchApproval=true`)
- 编成:`chtpl-generic-optimize-default` 四成员,**全员 harness=omp(真实 LLM 子进程,RPC 模式)**——生产主管(lead)/数据分析师/知识调优工程师/工艺工程师
- 对象:mock 产线(2 数控节点 A/B + 1 数采节点)· 配方 v1(A=160[130,180]st30 / B=70[58,88]st30)· 产品限界与四层联锁生效中
- 驱动方式:只发一条 goal 消息 + 人工在审批门裁决;其余编排/执行全部由真引擎自治

## 作业时序(真引擎自治,人工只做四件事:发 goal、两次裁决、一次劣化裁定)

1. **goal 下发(人 → lead)**:频道消息唤醒 lead,要求「分析 → 配方链路试验(会触发人工审批门)→ 复测 → 有进步才固化;步幅要小」。
2. **lead 三路编排(真 LLM)**:dispatch_task 派出「数据面取证」「知识库检索/调优方案」「执行面核实」三个子任务。工艺工程师按 lead 指令先核实执行面,发现**自己无节点绑定 → 硬阻塞上报 lead**(my_industrial_nodes 为空、param_read 被拒,零写入)。
3. **试探与 fail-closed(关键安全面)**:催办后工艺工程师立即提交 recipe_trial → **被节点绑定检查拒绝,零写入**,证据链上报。lead 随后用 `team_grant_nodes` 授予 A/B 两节点(它还自行根因了首次授权失败:「用了显示名而非规范 id」)。
4. **四成员数据协同**:数据分析师产出基线判读(5s 桶、越限统计、三电平开关波形发现);知识调优工程师产出调优方案 v2 并引用分析师数据;KB 落库在 401 后自愈成功(`exp-cc867127a599`,10 chunks)。
5. **HITL 第一路 · 拒绝+指导**:工艺工程师提交 recipe_trial(候选 A=163)→ 整批挂起等人工 → **人工拒绝并附指导「温度改 164、压力改 74」** → 指导逐字回流工具回包 → **PLC 不动、配方版本不变**。
6. **HITL 第二路 · 按指导修订+批准**:Agent 按指导修订为 **A=164/B=74 重新提交**(假设文本自带「上一版被人工驳回(幅度偏大),人工指定…」归因)→ 人工**批准并附言** → 整批 2/2 落产线,**PLC 回读 164/74 一致,试验未写配方版本**。
7. **诚实判读(劣化分支)**:数据分析师 8 分钟窗复测:**均值未上移(Δ=−0.29℃,噪声内)、离散劣化(sd +44%、5s 摆幅 6.95→12.90℃)** → 团队正确地**拒绝固化**;人工裁定「无进步 → 统一回退」→ 工艺工程师 `recipe_rollback(dispatch=true)`:定义回退 + **PLC 整批恢复 160/70**(回读一致,配方 id 稳定)。
8. **收口**:各子任务 complete_task;lead 复核收口;KB 沉淀失败案例。

## 实测抓出并修复的产品缺陷

**配方参数投影丢 `stepLimit`**(两处,已修复 + 回归 12/12):

1. `toolRecipeUpdate` 部分合并(`server/services/workshop/agents/industrial/ops-tools.ts`)——合并结果只带 nodeId/templateRef/value/min/max;
2. `revertToVersion` 快照回填(`server/services/workshop/dcw/dcw-recipe.repo.ts`)——同上。

后果链(本次实弹命中):同值 update 被误判为"有变化" → 空转增版(v1→v2),配方层单步限幅被静默抹掉;随后回退因两侧字段不再一致而绕过「完全一致,无需回退」守卫。修复后:

- 同值 update 不再增版,stepLimit 全程保持;
- 回退后 stepLimit 保持,重复回退被 409 干净拒绝;
- 回归断言:`.e2e-tmp/omp-e2e/reg.mjs` 12/12(同值不增版/变更增一次版/回退恢复/同值守卫/试验不写版本)。

## 附:已知非问题与说明

- `GET /api/workshop/ops-logs` 不支持 `action` 参数(支持 lineId/productId/recipeId/actorKind/kind/q/from/to)——早期测试脚本误用该参数造成断言空转,非产品缺陷;
- lead 首轮授权用显示名被拒后自根因改用规范 id——fail-closed 报错信息足以引导 LLM 自纠,无需产品改动;
- AEP 事件历史端点在该流量下为空(events 不落 mailbox/chat 路径),时间线证据以 mailbox + 审计为准。
