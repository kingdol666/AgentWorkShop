## 第三部分 · TII 适配性评估

### 3.1 强项（符合 TII 审稿人 taste，务必保留）

1. **真实协议传输**：治理结论经过 Modbus TCP 真实事务，而非只在内存 mock 上成立。
2. **论文—代码常量一致性审计（20/20 锚点）**：极少见，直接回应"常量不可追溯"的可复现性质疑。
3. **不变式形式化 + 动态验证**：I1/I2 有实现锚点与动态证据，不是口号。
4. **分层证据标签 L1--L4 且不跨层合并**：这是 TII 很吃的一套方法论。
5. **预注册协议**：先公布协议与臂、再填数字，规避 post-hoc 调参之嫌。
6. **诚实负结果**："attribution ≠ prevention"（消融臂照写、账本照记，但拦不住）是本论文最有价值的一句话。
7. **机器判定的复现门禁 + 篡改自检**（`compare.mjs`）：退出码语义 + 注入篡改必被拒。
8. **独立 Threats to Validity 小节**。

### 3.2 致命短板（按审稿人杀伤力排序）

1. **中心命题未测。** 摘要/结论承诺"治理开销 <15 % 换取 100 % 拦截"，而 E1b（agent-in-the-loop 开销）为空。唯一已测时延是 mock in-process（17--160 ms，受服务器开销主导），**既不是** LLM 提议→写入路径，**也不是**真实传输回读成本（仅 `tab:plc` 单次 21--48 ms）。审稿人会判：headline claim 是承诺，不是结果。
2. **零 baseline 实测。** B1--B8 全部 only "designed"。TII 的标准拒稿理由之一即"no quantitative comparison against baselines"——此处是"baseline 有设计、无数据"。
3. **实验章 5/8 小节是空壳**（标题带 "Released Protocol"）。容易被归类为 position/protocol paper，而非完整贡献。
4. **统计效力不足。** n=6 攻击、n=3 写入、1 次案例。论文以"管道是确定性代码，重复针对确定性而非统计"辩护——该论证只对 mock/无 LLM 路径成立；而**恰恰是 LLM-in-the-loop 路径非确定，且全空**。
5. **"人"的维度是模拟的。** E8 用 τ-bench 模拟操作员，不能以 human study 措辞呈现。
6. **单领域、单线、单种子。** L2（TEP/SWaT）与 L3（HIL）均 only designed，"realism"实际停在 L1 + PLC 模拟器。

## 第四部分 · 逐项判定：哪些测试有效、哪些无效或高风险

**必须保留（有效）**：s2 论文-代码一致性；api-3（F5 + 边界 + 双分支）；api-4（回读 + 归因）；plc-1/2/4（真实协议闭环与故障）；E1a 消融；以及待做的 **E5**（全论文唯一含算法含量的实验）。

**低效 / 需重构**：
- **s1 能力清单**（统计路由数、工具数、表数）——这是**代码度量，不是实验**。应移入 Artifact/附录，避免占用 Experiment 版面，更不能作为"evidence"呈现。
- **VII-D 表中的单值**（"8--9 points""21--48 ms"）——统计价值低。要么补 ≥20 次取分布，要么明示仅为 existence proof、不承载统计声明。
- **VII-C 的 rate 语言**——保留，但保持现有"conformance test"标注（论文这点做得对）。

**高风险 / 建议砍或降级**：
- **E7（AutoGen / LangGraph / CrewAI 对比）**——最大 straw-man 风险：这些框架需**等工程量**适配才公平，审稿人会直接质疑比较不公平，且 token 成本高。建议降级为"单 ReAct agent + 同一 MCP 工具面"这一个受控对照，其余移入 future work。
- **E8 模拟操作员**——要么做真人小样本（N≥8）并给伦理声明，要么改名 "scripted-operator reference" 并删净 "human study" 措辞。
- **B5（PID）**——把未整定的 PID 与 LLM 监督同台比较不公平；建议仅作"任务类别能力边界"的定性锚点。

## 附 · 图四（`fig:e1a`）渲染问题根因与修复记录

**原图症状**：柱位漂移/错位、两图柱位不可比、同一指标颜色语义混乱。

**四个根因**：
1. **pgfplots 的 ybar 自动分组偏移**：原图每个 `\addplot` 只含 **1--2 个坐标**，pgfplots 会按"系列序号"自动给柱加偏移，导致柱在类别槽内错位；且同一个 `\addplot` 内的两个点被当作同一系列，破坏了"绿=完好 / 红=被旁路"的颜色语义。
2. **两个独立坐标区**：上下两图各自的 `ymin/ymax/height` 不一致，柱高与柱位在两图之间不可比。
3. **`xtick=data` 陷阱**（修复中踩到）：它只取**首个系列**出现过的类别，使得另一臂的类别标签整体丢失（曾只显示 Full / No RB 两个标签）；必须显式列 `xtick={...}`。
4. **叠加右轴撑宽**：`axis y line*=right` 会把右轴的刻度与标签加在原轴包围盒**之外**，使整张图超出栏宽 19 pt（`Overfull \hbox`），也是右轴标签贴近邻栏的原因。

**修复方案**：
- 合并为**单个 `tikzpicture` + 单个坐标区 + 右侧叠加坐标轴**（双 Y 轴），一图承载两个指标；
- 每个柱序列用**显式 `bar shift=±8pt`** 固定柱位，彻底消除自动偏移；
- **显式 `xtick={Full,No intl.,No RB,Ung.}`**，四类标签齐全；
- 图例**横排置于坐标区下方**，避免压轴；
- 两轴宽度统一收窄为 `0.86\columnwidth`，消除 `Overfull`（现已 0 处）；
- 左轴=拦截率（绿=联锁完好 / 红=联锁旁路），右轴=治理写 p50（ms，蓝色），每柱直标数值。

**数据真实性验证**：新增 `bench/tools/fig4_analyze.py`，从**已发布的原始 CSV**（两轮 full-tier 运行 × 3 轮重复）按与 harness 完全一致的口径（接受写总体、nearest-rank 分位、逐轮 p50 取六轮均值）**独立复算**，四根柱复现误差 ≤ 0.03 ms：

| 臂 | 复算 | 论文原值 | 偏差 |
|---|---|---|---|
| Full | 130.48 | 130.5 | −0.02 |
| No intl. | 129.68 | 129.7 | −0.02 |
| No RB | 127.90 | 127.9 | 0.00 |
| Ungated | 120.63 | 120.6 | +0.03 |

拦截率同样在原始 CSV 上复现：36/36、24/36、36/36、24/36（即 6/6、4/6、6/6、4/6）。**结论：图四数值真实、可追溯、可复现；此前"渲染异常"是绘图代码缺陷，不是数据问题。**
