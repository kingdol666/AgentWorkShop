# 实验审计与写回说明

## 结论

用户提出的证据范围表、按运行路径组织结果、保留阴性结果的评价合理；“罕见”或“审稿人难以攻击”是主观判断，不能据此推断接收。有关最新记录的写回需作以下限定。

1. 九条记录是三批次中事后选取的 2+2+5 个探索性 episode，不是统一实验下的独立重复或 0/9 的可信统计。另有一个取消记录未纳入且隔离状态不明；四次未达隔离要求的调试记录另行排除。后续五次的初始保压设定不同。
2. 写事件收集器用终验时间倒推 60 秒，且从摘要中缺失的节点映射字段筛选写事件；现有台账缺少收集器用于归因的字段。部分 worker 流被截断为无法解析的 JSON 行。因而报告中的 NO_WRITE 和 Agent 写次数不能视作独立完整验证。现存本地台账的完整性也未冻结。
3. 一次脚本使用 worker 身份调用 recipe trial，批准由程序代理提供；响应报告模拟器写入已确认。稍后从可变本地写历史提取的条目在值和配方运行标识上匹配并记录 readback-verified，但不是独立硬件验证，也不是模型自主写入或真人审批。快照与其源文件哈希已放入 S7-agent-followup.zip。
4. 完成状态与目标带外过程值并存支持将过程核验作为独立判断；现有记录不足以单独证明特定改派路径的因果故障或平台修复。受测配置下，直接写工具/授权的可用性受限；recipe trial 是不同路径。两项作为治理观察与未来验证方向，不能声称已修复的普遍缺陷。
5. 窗口探针四场景分别 22/22、14/14、14/14、60/60，来自独立后续批次（配置窗口比例 0.8）；表格其他统计来自冻结批次，表头和图注已经说明不能合并。该批次的测试值和判定均来自同一配置，不能证明配置的工程正确性。

## 有效性与后续工作

保留原始实验统计及模拟器/模拟驱动边界。需要先修复采集器的事件时间、节点和 actor 关联，保存完整未截断轨迹及不可变服务/配置快照，再按预注册的纳入规则重新执行相同初态、统一时间尺度、随机条件顺序的配对试验，与命名的控制器基线比较。人类审批、真实设备操作和物理安全需各自的实验，不能由脚本批准或模拟回读替代。
