\section{System Architecture}
\system{} (v0.7.39) is an integration framework, not an application: in one Node.js process it ships the two halves that industrial deployments otherwise bolt together by hand---a REST and WebSocket API, an MCP server with 25 tools \cite{mcp2024}, an A2A agent interface \cite{a2a2025}, and a hot-reloading, error-isolated plugin host---under one authentication layer. Operators enter through a web console or TUI workbench sharing the same approval queue. Fig.~\ref{fig:arch} shows the complete architecture.

\subsection{Design Principles}
\emph{P1, node-native integration}: the agent and industrial runtimes execute in one process and one data domain, so binding, telemetry, and write control share invariants rather than APIs---hence \emph{check-then-actuate integrity}: the interlock test and the driver call run in one event-loop turn over the same process-local recipe-run state, and the window that authorizes a write cannot change between check and actuation. Co-residency governs the platform-internal path but does not contain the harness engines, which remain privileged local processes (containment is a deployment property; Sec.~IV-D).
\emph{P2, supervisory positioning}: \system{} occupies the supervisory, soft-real-time tier; hard real-time control and safety functions remain in PLCs, mirroring the IEC~61511 separation of basic control from safety instrumented functions \cite{iec61511}.
\emph{P3, configuration-driven, down to the plant scenario}: a typed configuration schema drives acquisition intervals, approval policies, retention, and memory budgets; driver configurations are derived from each device's integration export, and a named \emph{plant scenario}---devices, signal semantics, dynamics, recipes---re-instantiates the full deployment, so adapting to a new line is a configuration task (measured in Sec.~\ref{sec:port}).
\emph{P4, engine-agnostic governance}: agent intelligence is a replaceable component; the governance pipeline of Sec.~IV is defined at the tool boundary and is therefore identical for every engine.


\subsection{Industrial Half}
Five protocol drivers spanning four protocol families---Modbus TCP, Modbus RTU (over TCP), OPC UA \cite{iec62541}, MQTT, and HTTP/REST---sit behind a uniform, plugin-registerable driver interface; a mock driver supports deterministic testing. Each acquisition node runs an \emph{edge runtime} owning its sampling schedule and in-flight mutual exclusion, with three decoupled intervals: acquisition (default 5\,s, floor 1\,s, hard clamp $[0.1, 60]$\,s; sub-tick intervals wait for the 250\,ms sweep), WebSocket publish (default 1\,s), and display/trend (default 5\,s). A 250\,ms gateway sweep samples nodes under a non-accumulating budget of 64 in-flight samples per tick; a \emph{rotating cursor} plus per-node \emph{due check} stops not-yet-due nodes from consuming budget first, so tail nodes are never starved.

Each node's alarm state machine spans \texttt{ok}/\texttt{warn}/\texttt{alarm}/\texttt{offline}: 8\,\% warn band, 2\,\% hysteresis, three-frame \texttt{ok}$\leftrightarrow$\texttt{warn} debounce, watermark-based out-of-order defense, recipe-window violations as edge-triggered \texttt{alarm}; acknowledgment is a human step with escalation (default 15\,min). Time series persist to TimescaleDB (batched 500\,ms flushes, tiered retention), frames to MinIO with fallback to local disk, and platform state to SQLite (WAL, FTS5); every alarm, write, recipe change, and rollback row carries line, product, and recipe dimensions for Sec.~\ref{sec:eval}'s metric slices.

\subsection{Agent Half}
Fourteen engines are registered with a capability matrix (mid-task steering, supervision, human-in-the-loop, among others): an in-process deterministic mock (used in Sec.~\ref{sec:eval}), a first-party RPC engine (omp), and vendor or open-source CLI/SDK agents (e.g., codex, claude, qwen). Capabilities are asserted per engine and verified by the static audit (Sec.~\ref{sec:static}); dispatch follows an allow-list probe that resolves each executable and validates its response.

The collaboration unit is the \emph{channel}: a named room hosting one lead, its workers, the task tree, and the message history; teams deploy as a unit, and every industrial binding is scoped to its channel. Task trees carry seven states (\textsc{submitted}, \textsc{assigned}, \textsc{working}, \textsc{waiting} for blocked parents, \textsc{failed}, \textsc{cancelled}, \textsc{completed}). Each lead runs a supervision loop on a 1\,s tick with exponential idle backoff and event wake-up; each tick first assembles a state fingerprint (task tree, member queue depths, newest mailbox message) and skips the LLM call if unchanged---an idle plant costs no tokens unless a parent task is closeable. When consulted, the LLM owns goal judgment, completion, and escalation; mechanical decisions run every tick on a deterministic rule engine: FIFO dispatch to the worker with the shortest queue (ties broken by longest idle), reassignment of failed tasks while retries remain (limit 3), and a 300\,s stall watchdog treating tool activity as liveness. Both are ablated as E2/E3 (i.e., B6/B7), and their constants anchor the static audit (Sec.~\ref{sec:static}).

Agents accumulate typed memories (session, task, peer, team chronicle, reflection, semantic) in SQLite with FTS5 and an optional vector index. Retrieval fuses a lexical channel (FTS5) and a dense vector channel by reciprocal-rank fusion \cite{cormack2009rrf} ($k{=}60$), scores candidates by $0.5\,\rho + 0.3\,\phi + 0.2\,\iota$ (normalized relevance, kind-aware recency with 3--14\,d half-lives, access-weighted importance), diversifies by maximal-marginal-relevance \cite{carbonell1998mmr} ($\lambda{=}0.7$), and injects three layers under a 500-token budget. Compaction triggers at 70\,\% of the context window and harvests summaries back into memory.

\subsection{The Governed Bridge}
An engineer binds plant nodes to agents (single agent or whole team); the binding injects physical semantics into the agents' context and derives their tool surface---no separate integration layer to build or maintain. A bound node yields a \emph{semantic card}: physical quantity, unit and display precision, \emph{hard interlock} range, \emph{soft interlock} recipe window, warn band, live value with freshness, and a rule limiting any single step to 2\,\% of span. Bindings carry an operating mode: \emph{manual} (every agent write approval-gated), \emph{auto} (writes proceed under interlock and backstop), or \emph{unbound} (no write path); team members can share one node set, so a lead-dispatched task and a worker's actuation share one authorization scope. Agents never see register addresses.

Agents act through a host-tool surface of 48 tools, 23 of them industrial or automated-ML (the MCP server exposes a 25-tool subset), spanning setpoint control (\texttt{dcw\_control}), reading, judgment, rollback, audit, and recipe editing under approval. Two separations are architectural: \emph{judgment is not execution}---\texttt{dcw\_judge} records a keep/rollback/uncertain verdict but cannot actuate---and \emph{lead-only tools} are restricted to lead agents with approval.

\subsection{Digital Twin and Node-Binding Rendering}
Rendering binding is part of the integration model: a \emph{device-twin registry} persists, per scene entity, the bound 3D asset, the agent in charge (a virtual operator avatar), and the command set, alongside the three device-shadow state planes \cite{ditto2024} (\emph{telemetry}, \emph{desired}, \emph{state}). A WebSocket bus broadcasts lifecycle events and every reading, so the scene renders live values without polling; scene edits write back to the node registry, so the scene doubles as a commissioning editor that never actuates---\emph{desired}-to-\emph{state} reconciliation traverses the governed write path when it does (Sec.~IV).

\subsection{Production-Line Management}
The framework models a production line as a four-level object tree---line, product, recipe, \emph{run}---because every governance object of Sec.~IV hangs off it: the recipe window constrains writes jointly with the hard range while a run is active (Eq.~\eqref{eq:constraint}), acquisition samples only nodes on lines with an active batch (PLC-side protection persists between batches per P2), and the backstop scores open records against the active recipe window (Sec.~IV-B). The versioned, non-destructive recipe lifecycle spans editing (new version $n{+}1$), \emph{known-good} baseline freezing, \emph{known-good rollback} that re-dispatches the frozen set to the PLC, and one-click \emph{apply} of a fresh batch; an active run binds exactly one recipe version to one batch, giving every write a unique governance context---the window $W_r(p)$ of Eq.~\eqref{eq:constraint}. Off-window excursions have two bounded exits: automatic rollback while the executed-rollback count is below $K{=}2$ (Sec.~IV-B), then mandatory human escalation. Every operation lands in a central audit log with typed actor attribution (user, agent, system) and line/product/recipe dimensions; writes are also anchored in a signed journal with previous/new values, source, approval, and record identifiers---the substrate for \bench{}'s per-write attribution metric (Sec.~\ref{sec:bench}) and the case study's forensic queries (Sec.~\ref{sec:case}).
