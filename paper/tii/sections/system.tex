\section{System Architecture}
\label{sec:arch}
\system{} (v0.7.39) is an integration framework, not an application: in one Node.js process it ships the two halves that industrial deployments otherwise bolt together by hand---a REST and WebSocket API, an MCP server with 25 tools \cite{mcp2024}, an A2A agent interface \cite{a2a2025}, and a hot-reloading, error-isolated plugin host---under one authentication layer. Operators enter through a web console or a TUI workbench; agents enter through MCP or A2A; both meet on the same objects and the same approval queue. Fig.~\ref{fig:arch} shows the complete architecture.

\subsection{Design Principles}
\emph{P1, node-native integration}: the agent and industrial runtimes execute in one process and one data domain, so binding, telemetry, and write control share invariants rather than APIs---hence \emph{check-then-actuate integrity}: the interlock test and the driver call run in one event-loop turn over the same process-local recipe-run state, and the window that authorizes a write cannot change between check and actuation. Co-residency governs the platform-internal path but does not contain the harness engines, which remain privileged local processes (containment is a deployment property; Sec.~\ref{sec:hitl}).
\emph{P2, supervisory positioning}: \system{} occupies the supervisory, soft-real-time tier; hard real-time control and safety functions remain in PLCs, mirroring the IEC~61511 separation of basic control from safety instrumented functions \cite{iec61511}.
\emph{P3, configuration-driven, down to the plant scenario}: a typed configuration schema drives acquisition intervals, approval policies, retention, and memory budgets; driver configurations are derived from each device's integration export, and a named \emph{plant scenario}---devices, signal semantics, dynamics, recipes---re-instantiates the full deployment, so adapting to a new line is a configuration task (measured in Sec.~\ref{sec:port}).
\emph{P4, engine-agnostic governance}: agent intelligence is a replaceable component; the governed write path of Sec.~\ref{sec:writepath} is defined at the tool boundary and is therefore identical for every engine.

\subsection{Three Planes and a Governed Bridge}
The architecture has three planes. The \emph{agent half} couples 14 interchangeable LLM harness engines with lead-supervised teams (channels) and typed episodic--semantic memory, so that team organization, supervision, and learning are platform services rather than per-application code (Sec.~\ref{sec:channel}). The \emph{industrial half} terminates five protocol families in per-node edge acquisition runtimes, a starvation-free gateway sweep, an alarm chain, and line/recipe management---the supervisory data and control substrate (Secs.~\ref{sec:nodes} and \ref{sec:lineops}). The \emph{governed bridge} between them is the paper's object: binding a node to an agent injects physical semantics as a semantic card and derives a tool surface whose only write path is the governed pipeline of Sec.~\ref{sec:writepath}---48 host tools, 23 of them industrial or automated-ML, with the MCP server exposing a 25-tool subset. Two separations are architectural and span the whole system: \emph{judgment is not execution}, and \emph{lead-only tools} are restricted to lead agents with approval (Sec.~\ref{sec:hitl}).

Beneath all three planes lies \emph{one data domain}: time series, frames, platform state, and a signed audit journal with typed actor attribution, all carrying line/product/recipe dimensions (Sec.~\ref{sec:lineops}). The device-twin registry lives here too, feeding a three.js scene that renders live state through a WebSocket bus but never actuates (Sec.~\ref{sec:lineops}).

\subsection{How the Pieces Collaborate}
The deployment lifecycle runs left to right through Fig.~\ref{fig:arch}. An engineer connects a device---export, connectivity test, node creation, line/product/recipe provisioning, binding---which creates nodes carrying semantic cards (Sec.~\ref{sec:nodes}). A team deploys into a channel and is bound to the nodes it may operate (Sec.~\ref{sec:channel}); the binding mode fixes the human control boundary for everything the team does (Sec.~\ref{sec:hitl}). From then on the team works the loop: observe fresh process values, propose setpoint moves that become governed writes inside the batch context (Secs.~\ref{sec:writepath} and \ref{sec:lineops}), verify and judge outcomes, and learn them into memory, with the backstop bounding any excursion the team leaves behind (Sec.~\ref{sec:loop}). Recipes version and roll back non-destructively (Sec.~\ref{sec:recipe}). Section~\ref{sec:eval} measures each stage of this narrative on a live instance.
