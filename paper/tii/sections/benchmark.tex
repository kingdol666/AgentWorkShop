\section{\bench{}: Benchmark and Experimental Protocol}
\label{sec:bench}

\subsection{Design Principles and Data Layers}
\bench{} is built on three principles. \emph{Determinism}: a seeded PRNG (mulberry32) and a scenario-snapshot API make structural metrics (interception verdicts, judge-class checks) point-wise reproducible; objective values over \emph{sampled} process variables remain timing-sensitive (Sec.~\ref{sec:repro}); the offline grid-search optimum $W^{*}$ is the reference bound. \emph{Layered realism}: results are reported per data layer (Table~\ref{tab:layers}), never pooled, so claims carry their realism level. \emph{Executable protocol}: the released audit harness (\texttt{bench/run.mjs}; four seeded tiers) executes the artifact and invariant checks of Secs.~\ref{sec:static}--\ref{sec:dynamic}; the E1--E9 campaign configurations are declarative documents (E-numbers instantiate the B groups; E8 = B4).

\subsection{Tasks, Faults, Metrics, and Baselines}
Five task families cover the supervisory workload, each judged by a machine-readable oracle over the database, readback values, and event streams, never log strings: \emph{T1} closed-loop setpoint correction in-window; \emph{T2} out-of-window excursion; \emph{T3} multi-node joint adjustment under the step rule; \emph{T4} batch parameter recovery; \emph{T5} mid-run objective change and re-planning. Six fault families inject at the simulator control API: F1 step drift, F2 sensor freeze, F3 communication interruption (30\,s), F4 out-of-order injection, F5 out-of-window writes, F6 storage unavailability---F5 stresses governance (I1), F6 degraded-mode integrity.

Metrics form three families. \emph{Safety} metrics require the governed pipeline: out-of-window write interception rate (denominator = seeded attacks), readback-failure capture rate, false-block rate (denominator = legal in-window writes attempted), spurious-rollback rate, and per-write attribution rate (target 100\,\%). \emph{Performance} metrics cover the \emph{automatic segment} (proposal acceptance to verified write), kept separate from human-approval waiting time so human response is never conflated with system latency. \emph{Cost/quality} metrics cover task goal rate, tokens and LLM calls per task, approval wait time, and human interventions per task.

Eight baseline groups are defined. B1 ablates the pipeline's own mechanisms (bench-mode-only bypass switches). B2--B3 isolate the platform from its intelligence: they run general frameworks (AutoGen \cite{wu2023autogen}, LangGraph \cite{langgraph2024}, CrewAI \cite{crewai2024}) and ReAct-style prompting \cite{yao2023react} on the same MCP tool surface \cite{mcp2024}. B4 is a human-operator reference under the $\tau$-bench paradigm \cite{yao2024taubench}; B5 anchors against classical control with $W^{*}$ as reference; B6--B7 are the scheduling and memory arms of Sec.~III-C; B8 replicates tasks across real engines.

\emph{Reproducibility protocol.} \emph{Released today}: the harness executes every check of Secs.~\ref{sec:static}--\ref{sec:dynamic} with fixed seeds; every run records its seed, harness source hash, and commit, appends to never-overwritten timestamped directories, and yields judge-class metrics identical across executions (latency is environment-dependent and reported as ranges). \emph{Specified, in development}: the campaign runner, the statistics module (Mann--Whitney $U$ with Holm correction, bootstrap 95\,\% CIs; unit of analysis = run), the fault injector, and the decision-log instrumentation persisting each LLM decision's prompt hash, model version, and token usage. Released LLM arms pin model versions; temperature-0 applies to the campaign configurations.
