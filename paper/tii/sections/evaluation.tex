\subsection{Setup}
\label{sec:setup}
All results in this section were produced by one executable pipeline (\texttt{bench/pipeline.mjs}) that boots the plant simulator and the platform, provisions the plant over real protocol transports, drives the governance surface, runs the closed-loop campaign, and writes a machine-readable archive. A single command reproduces the section:
\begin{center}\footnotesize\texttt{node bench/pipeline.mjs --profile integrated --seed 42 --cl-seeds 3}\end{center}
The pipeline emits no result it did not measure: every reported number below is read from the evidence records of the never-overwritten run directory. Each run records its seed, the harness source hash (SHA-256 over the eight pipeline checker sources, \texttt{204fc9ee} here), the repository commit (\texttt{d6c824d}), the Node/platform, and the full evidence chain. Host environment: \resHost{}.

The pipeline executes fourteen stages: preflight and bootstrap (P0), plant-model instantiation with the offline optimum (P1), multi-line provisioning over five protocol drivers (P2), acquisition, write-control and interlock checks (P3), the deterministic tool-level control loop over three observe--actuate--judge cycles per line (P4) with rollback/record/ledger surface (P4b), approval gate (P4c), audit reads (P4d), recipe lifecycle (P4e), the closed-loop optimization benchmark (P6), multi-modal acquisition (P7), the cross-scenario portability check (P8, Sec.~\ref{sec:port}), the system-backstop drill (P8b, Sec.~\ref{sec:govsurface}), and the platform-subsystem benchmarks (P9, Sec.~\ref{sec:govsurface}). Stage numbering follows the released protocol (no P5). A full run over five devices completes in about 5.2\,min; the closed-loop benchmark contributes about 36\,s per plant seed and the backstop drill a cadence-bound ${\sim}120$\,s observation window.

\emph{Headline results.} Across both scenarios the pipeline intercepted 33/33 seeded out-of-window/range writes (Wilson 95\,\% [89.6\,\%, 100\,\%], zero false blocks), recommissioned the deployment onto the second scenario with zero platform code changes, recovered 97.0--97.2\,\% of the offline grid optimum in the governed closed loop under a fixed controller, and exercised the backstop end-to-end ($\sim$120\,s). An LLM agent team closed the same loop over real transports through the same path, but reached only a median 0.76 of that optimum (Sec.~\ref{sec:case}).

\emph{Scope.} The reported run exercises tasks T1--T2 and faults F2/F3/F5 against baseline group B1; T3--T5, F1/F4/F6, hardware-in-the-loop, public-dataset replay, cross-engine replication, and baselines B2--B8 are covered by the released campaign designs and are \emph{not} reported here. All measured layers are simulation-tier (Table~\ref{tab:layers}).

\subsection{Cross-Scenario Portability (Framework Claim)}
\label{sec:port}
The framework's central claim---adapting the deployment to a new production line is a configuration task, not an integration project---is measured directly by the pipeline's final stage. The pipeline first provisions everything below on the \emph{cast-film physics} scenario (ODE plant model, six actuators, seven sensors, five protocol drivers, vector and image frames). It then switches the plant to a second, independently defined scenario, \emph{film-line}: a coating-oven line with a disjoint signal domain, driven by per-signal strategies rather than a physics engine. No scenario-specific code exists in the commissioning path: the identical five-step flow (export $\to$ connection test $\to$ node creation $\to$ line/product/recipe provisioning $\to$ agent binding) re-instantiates the deployment on both scenarios, because driver configurations are derived from each device's export at runtime (Sec.~III-A, P3).

Measured on the second scenario: five devices across all five protocol drivers are commissioned in one pass---the commissioning artifact is five driver configurations derived from the devices' exports plus one scenario identifier---three writable-setpoint devices become governed lines (Modbus TCP, OPC UA, MQTT), the two acquisition-only devices attach as satellites; all five nodes stream live data (9--12 one-second buckets); governed writes are accepted with readback deviation $0.04\,^\circ$C on Modbus TCP and exact on OPC UA; and all nine seeded out-of-window attacks are rejected with zero false blocks (0/3 legal in-window writes). The stage completes in about half a minute and the rig is restored. The structural verdicts are identical across scenarios---100\,\% interception, 0\,\% false blocks: per-line engineering moved into authoring the scenario definition, while the platform absorbed the difference unchanged.

Fig.~\ref{fig:walkthrough} shows that same commissioning path as an operator drives it on the live instance, and the four surfaces that carry it. \emph{(1)~Provisioning}: a device is registered as a \emph{node} whose protocol driver, sampling cadence and line are configuration derived from the device's integration export, so a real Modbus-TCP node and replayed mock nodes coexist in one acquisition loop, and a connection test gates creation. \emph{(2)~Binding}: a control node is attached to a device twin and a recipe window, which is why the process window travels with the deployment rather than with a line-specific program. \emph{(3)~Team composition}: the agent side is a \emph{team}---exactly one lead plus harness-backed workers---deployed as a unit into a channel; because the harness is a replaceable component, one team definition runs on an LLM engine or on the deterministic replay engine. \emph{(4)~Operation}: from then on the plant speaks back through the governed loop---each write opens an optimization record, \texttt{dcw\_judge} resolves it to \emph{keep} or \emph{rollback} with a reason, and the ledger renders the record history against the setpoint history annotated by source (\emph{agent}, \emph{manual}, \emph{recipe}, \emph{rollback}). Together these four surfaces are the whole commissioning-and-operation path, and no plant-specific code appears in any of them: this is the integration claim of Sec.~III made operational.

\subsection{Static Capability and Artifact-Consistency Audit}
\label{sec:static}
Before any dynamic campaign, the released audit harness (\texttt{bench/run.mjs}) verifies the artifact at the source level, because a paper whose constants cannot be traced to code is not reproducible in any meaningful sense. Three checks run offline: a \emph{capability inventory} against the claims of Sec.~III; a \emph{paper--code consistency} check that locates 20 representative quantitative constants cited in this paper (sweep quota 64, breach threshold 3, rollback-chain limit 2, RRF $K{=}60$, MMR $\lambda{=}0.7$, compaction 0.7, watchdog 300\,s, hysteresis 2\,\%, and others) at their implementation anchors; and a \emph{pipeline stage-ordering} check asserting that the governed-write stages of Algorithm~1 appear in the declared order at their source anchors. All pass: 20/20 anchors and 2/2 ordering chains---engineering discipline rather than validation evidence, since the harness audits the artifact it belongs to; a future edit that invalidates a claim fails this audit rather than surfacing in review.


\subsection{Dynamic Invariant Verification on a Live Instance (L1-Tier API Surface)}
\label{sec:dynamic}
The static audit verifies structure; this subsection verifies \emph{behavior}: L1-tier evidence (Table~\ref{tab:layers}), driving a pinned platform instance (v0.7.39, mock drivers) exclusively through its REST API with seeded randomness (mulberry32, seed 42). A benchmark line is created with global safety range $[120, 260]\,^\circ$C and a batch is started with active recipe window $[175, 205]\,^\circ$C; the safety invariants of Sec.~IV-E are then attacked and probed, including the decision boundaries and both branches of Eq.~\eqref{eq:constraint}.

\emph{I1 (containment).} Six seeded gross out-of-constraint writes---global-range violations (107, 269), window violations while the batch is active (219, 163), and extreme/negative values ($10^6$, $-25$)---are all rejected with typed validation errors; simultaneously, all three in-window control writes are accepted, so the interception rate is 100\,\% at a false-block rate of 0\,\%. Boundary probes at $\pm$one least-count behave as specified (205.0 accepted; 205.1, 174.9 rejected). The rejection message cites the window as the binding constraint---the global range is stated not to apply to the running batch (original retained in the released evidence). With the batch stopped, the window branch deactivates and the hard range alone governs: an out-of-range write (300) remains rejected while a within-range, out-of-window write (130) is accepted---confirming that the soft interlock is a batch-scoped constraint, not a constant.

\emph{I2 (readback closure) and attribution.} All accepted writes return a driver readback within the tolerance of Eq.~\eqref{eq:tolerance} ($\tau = 0.7\,^\circ$C at one decimal digit and a 140$^\circ$C span), and all produce journal anchors with source, actor, timestamp, and previous/new values---a 100\,\% attribution rate. Acquisition held the 1\,s cadence, and the samples API answered 20 probes at p50 6--22\,ms / p95 8--63\,ms.

\emph{Reproducibility.} Every execution on a pinned harness---the two identical-harness pipeline runs of Sec.~\ref{sec:repro} and the released ablation runs (three aggregated in Sec.~\ref{sec:e1a})---produced identical judge-class metrics: the same seeded attacks, rejections, boundary verdicts, and ledger outcomes; only fixture identifiers and latency varied. A machine verdict is part of the archive: \texttt{bench/compare.mjs} re-runs the pipeline and asserts judge-class equality against the archived baseline (\textsc{reproducible}; the gate rejects a tampered metric, validated by a self-test). The Wilson 95\,\% interval for 6/6 trials ([61\,\%, 100\,\%]) is the honest reading of any small-$n$ rate.

\emph{Scope.} These checks exercise the pipeline's accepted-action language at the API boundary with the LLM out of the loop---deliberately so, since the invariants are defined over the pipeline, not over any engine (Sec.~III-A, P4).

\subsection{Real-Protocol Plant Scenarios (Five-Protocol PLC Node Simulator)}
\label{sec:plc}
The API-tier checks of Secs.~\ref{sec:dynamic} and \ref{sec:e1a} use in-process mock drivers; this subsection re-runs the working-condition scenarios over \emph{real protocol stacks}, against an independent five-protocol PLC node simulator (Modbus TCP/RTU slaves, OPC UA server, MQTT broker/publisher, HTTP endpoints, with an ODE plant model). Driver configurations are derived at runtime from the simulator's integration-export API---no hand-written connection settings---and every candidate driver passes the platform's connection test before a node is created.

The pipeline provisions one production line per device that exposes a writable setpoint (4 lines: Modbus TCP, OPC UA, MQTT, HTTP) and attaches the acquisition-only device (a Modbus RTU gel counter) as a \emph{satellite} acquisition node on the first line, because the platform's acquisition gate samples only nodes whose line has an active batch. All five nodes stream live data through their real transports (2--14 one-second buckets in the settle window, Table~\ref{tab:plc}). A governed setpoint write costs 19--112\,ms (p50) depending on the protocol, with the Modbus TCP transaction dominating and its p95 reflecting the first write's connection setup on the freshly created fixture; readback closes within $0.04\,^\circ$C on Modbus TCP and exactly on OPC UA, while the MQTT and HTTP control channels report no readback by design (publish-only / echo-only actuators)---a driver property the write path records rather than conceals. Six seeded out-of-window and out-of-range attacks are rejected on \emph{every} writable protocol (6/6 each; 24/24 pooled, Wilson 95\% interval [86\,\%, 100\,\%]) with zero false blocks on the four legal in-window writes, and the deterministic tool-level control loop (\texttt{daq\_query}$\to$\texttt{dcw\_control}$\to$\texttt{dcw\_judge}) converges on all four lines. A link-interruption drill (simulator protocol service stopped and restarted) is both detected by the platform and recovered, and a process-freeze injection demonstrates defense in depth: the governed write still passes (readback verifies the register, not the process), and the failure is caught within 2\,s by the independent recipe-window monitor---precisely the layer separation of Secs.~\ref{sec:dynamic} and IV-D.

\subsection{Governance Surface: Recipe Lifecycle, Rollback, and Approval}
\label{sec:govsurface}
This subsection measures the \emph{lifecycle objects} the governance stack manages, because a governed loop that cannot version, revert, and attribute its own recipes is not deployable. Each probe below ran end-to-end in one pipeline run, with the LLM out of the loop. \emph{Non-destructive history}: a revert \emph{creates} version~3 rather than overwriting. \emph{Judge--execute separation}: judging \texttt{rollback} changed no PLC value ($196.60\,^\circ$C throughout)---only the separately invoked rollback restored the origin value ($203.40\,^\circ$C); an agent's verdict is an intent record, not an actuation. \emph{Bounded autonomy in action (backstop drill)}: freezing the process variable out of window under an open auto-binding record triggers the backstop---the record is judged \texttt{rollback} \emph{by the system} and the PLC restored to the baseline ($186.2\pm0.75\,^\circ$C), cadence-bound at ${\sim}120$\,s; chain limit $K{=}2$ remains specified (Sec.~\ref{sec:limits}). Default non-execution: in manual mode an agent write blocks until the approval releases it (148.2\,rpm on OPC UA; decision latency 456\,ms, approval-poll inclusive); the journal holds ten anchors over four sources and both log surfaces return full 200-entry windows.


\emph{Platform subsystems (P9)}: a mock lead dispatches a child task that a worker completes (parent \textsc{completed}); duplicate team-memory writes under one deduplication key yield one entry; the registry enumerates 14 engines (12 environment-available here).

\subsection{Closed-Loop Optimization Benchmark}
\label{sec:clbench}
This subsection quantifies how much of the offline optimum a \emph{governed} closed loop recovers on the cast-film twin. The pipeline instantiates all six actuators (zones on Modbus TCP, screw on OPC UA, line speed on MQTT, die gap on HTTP), starts a batch off-optimum ($N{=}150$\,rpm, $v{=}95$\,m/min, zone $200\,^\circ$C), and runs a controller that reads through the acquisition path and writes through the governed path. The objective
\begin{equation}
J = 55\,J_\text{thick} + 25\,J_\text{quality} + 8\,J_\text{energy} + 7\,J_\text{throughput}\label{eq:objective}
\end{equation}
constrains melt temperature to $[195, 225]\,^\circ$C and pressure to $\le 22\,MPa$.

The controller is model-light and fixed in advance: it inverts $h\propto N/v$ at constant line speed ($N\leftarrow N\cdot(50/h)$, $\pm$22\,rpm per step) and corrects the heater setpoint only when melt temperature leaves $[196,224]\,^\circ$C. It contains no LLM, so the benchmark isolates the \emph{governed loop} rather than a particular model. Convergence requires two consecutive evaluations with $h\in[48,52]\,\mu$m, defect $<2\,\%$, pressure $\le22$\,MPa.

Fig.~\ref{fig:clbench} reports the trajectories; $J_{\text{end}}$ is the mean of the two consecutive in-band evaluations (the plotted iteration-1/2 pair). From $J_0=64.7$--$70.2$ the loop reaches $J_{\text{end}}=87.2$--$87.4$ against the offline grid optimum $W^{*}=89.894$ (weights unnormalized, 0--95 scale; real-time physics), i.e.\ 97.0--97.2\,\% of the optimum, converging in two iterations with at most two governed writes per seed, no rejected write and no constraint violation; mean wall time is 36\,s per seed. Thickness moves from 55.2--56.1\,$\mu$m (target $50\pm2\,\mu$m), defect settles at or below 0.64\,\%, pressure at 16.6--16.9\,MPa, and melt temperature stays inside $[195,225]\,^\circ$C. Per-seed values ($J_0 \to J_{\text{end}}$, ratio): seed 42: 68.07$\to$87.26 (0.971); seed 43: 70.21$\to$87.16 (0.970); seed 44: 64.69$\to$87.37 (0.972). Repeating the campaign across the day's released runs keeps $J/J^{*}\in[0.966,0.973]$ (three runs $\times$ three seeds; the three run-level means are $0.971\pm0.001$, sd, $n{=}3$); the residual spread reflects the sampled process variables from which $J$ is computed. The 3\,\% shortfall is a throughput/energy trade, not a control failure: the grid optimum sits at a low-throughput corner where the objective's energy weight slightly exceeds its throughput weight, while the loop holds the higher line speed it started from.

\subsection{E1a: Pipeline-Tier Governance Ablation (Completed)}
\label{sec:e1a}
Using the env-gated bench-mode bypass (production builds refuse the flag), we compare the full pipeline against the three ablation arms of B1---soft interlock bypassed (\texttt{no-interlock}), readback verification bypassed (\texttt{no-readback}), and fully ungated---on the live instance (mock drivers, seed 42, three repetitions per arm per released run, fresh fixture per repetition). Because the hard range is enforced structurally at the driver layer and cannot be bypassed, the ablation isolates exactly the two bypassable mechanisms. Fig.~\ref{fig:e1a} reports the result; values were identical across repetitions (deterministic pipeline). Three findings: (i) bypassing the interlock collapses interception from 6/6 to 4/6 (identically in the no-interlock and ungated arms)---the window-class attacks execute while global-range attacks remain structurally rejected; (ii) the executed breaches are fully journaled (twelve out-of-window anchors per run: six breach writes plus six accepted edge probes, both bypass arms): \emph{attribution is not prevention}; (iii) no arm adds latency resolvable at this tier (p50 110--141\,ms, p95 150--169\,ms across all arms). Boundary behavior follows each arm's specification (9/9 probes = three probes $\times$ three repetitions; Wilson 95\,\% interval [70,100]\,\%), false blocks are 0/3 in every arm, and the no-readback arm is behaviorally identical to Full on in-memory drivers (the mock readback echoes the command)---its verification value is exercised by the frozen-process injection above.

\subsection{Case Study: LLM-Agent Closed-Loop Optimization (L4)}
\label{sec:case}
The benchmark of Sec.~\ref{sec:clbench} isolates the governed loop under a fixed controller; this subsection reports the complementary result---the same plant and objective closed by an LLM agent team---and it is a candid one. Four campaigns are released (first-party \texttt{omp} engine driving glm-5.3-flash in a lead-supervised team; manual-mode bindings; physics accelerated $6\times$; seed 42; plant and objective as in Sec.~\ref{sec:clbench}). In each campaign the team opened an optimization record, probed the plant with \texttt{daq\_query}, and actuated through \texttt{dcw\_control} over real protocol transports (Modbus TCP, OPC UA, MQTT, HTTP); the ledgers record 7, 7, 15 and 10 governed writes respectively, each attributable from journal anchors and the audit log, with the approval gate traversed on every write (approvals granted by the campaign's scripted operator emulation under the campaign operator identity---an autonomous-campaign configuration, not a production posture).

The outcome does not flatter the agent. The agent objective reached $J_{\text{agent}} = 67.7$, $31.2$, $68.3$, $68.5$ against $W^{*} = 89.894$---$0.75$, $0.35$, $0.76$, $0.76$ of the offline optimum, median $0.76$---and the thickness window $50\pm2\,\mu$m was \emph{not} reached: three campaigns settled at a $55.33\,\mu$m window mean and the fourth produced no in-window samples, while the melt-pressure node failed its connection test on OPC UA in all four. Of 39 acceptance checks per campaign, 33--35 passed, the failures being the pressure node, the inspector audit, the thickness window, and the objective check.

We report this as a negative result with a design implication. It supplies the existence proof the framework needs---an LLM team drove real protocol transports through the governed path with every write reconstructable---while showing that on this objective the team does not match a two-step fixed controller ($0.76$ vs $0.97$ of $W^{*}$). That is the propose/dispose division of labour working as intended: the agent explores and proposes, and the deterministic path is what converts proposals into converged actuation. It also sets the bar the released agent-in-the-loop campaigns (E1b, E2, E3) must clear before an LLM supervisor can be claimed to add value over that path.

\subsection{Reproducibility and Threats to Validity}
\label{sec:repro}
Reproducibility is separated into what is exactly reproducible and what is not. Re-running the whole pipeline twice with an identical harness (source hash \texttt{204fc9ee}), seed, and commit yields \emph{bit-identical} structural results: 55/55 pipeline checks pass in both runs; every seeded attack is rejected with zero false blocks on \emph{both} plant scenarios (9/9 on the second); all four per-line loops converge; the portability aggregates and backstop drill outcomes are identical; and $W^{*}=89.894$. What varies is what the abstraction predicts: governed-write latency is environment-dependent, and the closed-loop objective---computed from \emph{sampled} process variables---lands in $J/J^{*}\in[0.966,0.973]$ across campaign repetitions. Every run appends to a never-overwritten timestamped directory; the archive for this revision holds more than 90 run records across tiers, each carrying its seed, harness hash, and commit.

\emph{Threats to validity}. \emph{Construct}: success oracles are database- and readback-defined, mitigating self-reported success bias. \emph{Internal}: temperature-0, pinned-version LLM arms reduce but do not eliminate variance; hence mock-arm matrices with LLM spot-checks and nonparametric tests. \emph{External}: all measured layers are simulation-tier (two seeded plant scenarios, bounded by the ODE twin's fidelity); public-dataset replay (TEP, SWaT) is designed but unmeasured; the four LLM campaigns share one seed and carry no cross-seed variance estimate. Results are layer-labeled (Table~\ref{tab:layers}) and we claim no transfer beyond L1--L3--L4 without per-layer evidence. \emph{Conclusion}: the closed-loop result is reported over a fixed, pre-declared controller and three plant seeds, and the LLM campaign is reported as a measured negative rather than as a headline.
