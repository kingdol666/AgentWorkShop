\section{Related Work}

\subsection{Advisory-Boundary Systems}
Industrial LLM applications cluster into advisory families. \emph{Diagnosis and assistance} couples LLMs with knowledge structures: CoMA-IKG automates the construction of industrial knowledge graphs with an LLM-driven multiagent framework, supporting fault diagnosis \cite{zhang2026comaikg}; surveys chart the breadth \cite{raza2025industrial}. \emph{Engineering automation} generates control code: Agents4PLC verifies generated PLC code against formal specifications \cite{liu2026agents4plc}, and MetaIndux-PLC steers generation with control-logic guidance \cite{ren2025metaindux}. \emph{DT-coupled agents} parameterize simulations \cite{xia2024llmsim}, use a twin as prompt knowledge base and validation sandbox \cite{gill2025llmdt}. All share two boundaries: the output reaches a human or a compiler, never an actuator, and in the DT family the twin is the \emph{destination} of agent action, whereas in \system{} the twin is one observer of a real protocol stack and the destination is the plant. \emph{Closed-loop LLM control}, the newest family, removes the advisory boundary itself: LLM agents have converted fault detections into constraint-aware fault-tolerant control actions on simulated plants \cite{vyas2026ftc}, and tool-equipped LLMs have controlled real machines in natural language over OPC UA \cite{hofmann2025nlc}. LLM agents also actuate physical equipment in adjacent domains---autonomous chemical experimentation \cite{boiko2023autonomous} and robot control \cite{vemprala2023robotics}---but target single-apparatus loops, not production lines. These works demonstrate the feasibility this paper builds on, yet couple one agent (or team) to one protocol stack with per-application governance; none contributes a reusable integration substrate (protocol-heterogeneous, node-native, team-level binding) or a reproducible governed-write benchmark, which is the gap \system{} fills. The alarm chain of Sec.~III-B follows alarm-management practice (ISA-18.2) \cite{isa182}.

\subsection{Governed Execution, Benchmarks, and Frameworks}
Outside industry, $\tau$-bench \cite{yao2024taubench} supplies the evaluation paradigm we adopt for approval-gate semantics. Hard action enforcement has its own line---control barrier functions \cite{ames2017cbf} and shielding \cite{alshiekh2018shielding}; here the wrapped component is an \emph{agent tool surface}, and the fallback path (interlock, approval, readback, journal) is itself part of the audited contract. Approval semantics rest on levels-of-automation research \cite{parasuraman2000model}. The line/product/recipe/run tree of Sec.~III-F combines ISA-95 level integration \cite{isa95} with the ISA-88 recipe/batch model \cite{isa88}, and the semantic card is the node-level counterpart of the Asset Administration Shell (IEC~63278) \cite{iec63278}. General agent benchmarks \cite{liu2024agentbench} involve no physical plant or actuator safety contract; industrial datasets (TEP \cite{downs1993tep}, SWaT \cite{goh2017swat}) target fault diagnosis, not agent closed-loop control---\bench{} bridges the two. Orchestration frameworks (AutoGen \cite{wu2023autogen}, LangGraph, CrewAI; on ReAct \cite{yao2023react}) provide scheduling but no protocol layer, semantic grounding, or write governance, so they are treated as baselines over the same MCP tool surface \cite{mcp2024}. Network segmentation follows IEC~62443 \cite{iec62443}, complementing IEC~61511's separation of basic control from safety functions \cite{iec61511}; \system{} applies that separation at the agent--plant layer. The defining gap \bench{} occupies is the combination of node-level agent integration---one runtime, one data domain, team-level node binding---with closed-loop actuation under a formalized governance pipeline, per-write attribution, and a released benchmark.
