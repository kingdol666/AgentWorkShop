# Supplementary evidence: manuscript audit bundle

This is an evidence-index and selected, privacy-filtered material package; it is not a fully reproducible run environment. It does not replace the historical Supplementary File S1. Review the files and journal submission rules before uploading. `MANIFEST.json` identifies each source, the original SHA-256, delivered SHA-256, and transformations or omissions. The sensitive-data scan is heuristic, not a guarantee of anonymity.

## Experimental overview and figures

`EVIDENCE-OVERVIEW.md` gives the task-level R20 outcomes, preserved source limitations, four scenario targets and results, captions, and portable plotting commands. `real-harness/R20-TRACE-JOINS.csv` preserves the original matrix’s task and run-tag relationships with pseudonymous identifiers. `figures/` and `plotting/` contain the two figures, data-dependent plotting programs, and a basic alignment helper. The overview specifies which records remain unavailable in this bundle.

## Four deterministic simulator missions

`four-missions/` contains transformed text of four scenario mission logs and the additional BOPET transcript. UUIDs are consistently pseudonymized; internal short identifiers remain simulated runtime record identifiers. The BOPET transcript is corroboration of the same BOPET trajectory, not another run. The figure data are the manuscript CSV, JSON and source-data manifest. Each scenario has one deterministic direct-node trajectory; the September integrated report says no real-LLM P5/P5b log was generated in that run. Do not describe these four missions as model-driven. The executed runtime snapshot was not retained completely; annealing lacks final tensile-strength and defect measurements, and wastewater lacks a complete final effluent vector. Reported final annealing and wastewater values are separate mission-summary endpoints.

## Model-driven registered harness, R20

`real-harness/` contains the previously curated summary, a minimal table and a projection of the machine-readable evidence. R20 used a registered OMP adapter and GLM-5.3-Flash on v0.8.0 working-tree software; it contains six sequential tasks across two simulated scenes. Each task had a prevalidated three-value candidate set and a synthetic approval. All six retained a verified trial receipt and an explicit, run-tagged post-trial probe; all six probes were outside target. Repeated tasks shared simulator instances, and therefore are not independent process replications. A local SQLite fallback was used because the isolated online queue and Timescale endpoints were unavailable. Task state was checked after the probe; no task-completion-to-probe timing is established. Source reconstruction is conditional on base repositories, dependencies, OMP and external model service. Independent provider request/response logs were not retained here; do not claim complete reasoning or token/cost traceability. The projection removes record IDs and internal fields, so consult the access-controlled raw evidence to audit joins. The excluded R20 application trace contains 2314 UUID occurrences and local endpoint URLs; the full evidence JSON includes user names and runtime path fields. Cross-file pseudonymization and contextual privacy review were not established for those complete sources.

## Entry and component checks

`integration/` gives the existing R21 and R22 descriptions. R21 uses a fixed-call OMP fixture with no model request; R22 is direct REST with no task or harness. Both use synthetic approval and local simulator probes and do not establish route equivalence or target attainment. The approval-context tests indexed in the manifest are mock-driver component tests; they do not measure human-review effectiveness or plant safety. The onboarding replay is separate, uses a simulator, and its full local log is omitted from this public-oriented bundle.

## Historical model runs and protocol checks

Two older OMP logs are provided with UUID pseudonyms in `historical-model-runs/`. The staging copies match their benchmark source byte for byte before pseudonymization; the manifest records both hashes. Full historical runtime snapshots were not retained. These are task/channel transcripts, not complete provider-level model-request records. They belong to the same historical campaign, not to R20 or the four current missions. The goal-loop report's 51.7 final six-bucket mean and 52.02 separately logged window mean are different quantities and must not be interchanged. The model transcript also incorrectly describes the ranges 51.42–53.00 and 51.03–52.56 as wholly within 52±0.8; their extrema cross 52.8 and 51.2 respectively. Retain the transcript as a record of model output, not proof of all-sample compliance. The September protocol summary reports five local simulator protocol connections, but the current archive lacks the complete per-sample trace and the referenced protocol-run folder. It supports a bounded summary only.

## Historical multi-harness acceptance (October 20)

The manifest indexes a report and a team-line JSON from an older v0.7.67 build; neither is distributed because detailed identity and environment disclosure has not been reviewed. The report describes actual OMP and Copilot tasks with a mock lead; the other twelve harnesses were not demonstrated as real successful model runs. The recipe operation reported four of five device receipts verified, with the remaining MQTT receipt a transport acknowledgment. The report also records six TUI failures in its final round despite separate API/browser checks passing. Do not represent this as a current-version evaluation, five verified receipts, a 14-harness pass, or a complete HITL UI pass.

## Interpretation limits

All process tests described here use local simulators, not physical plant equipment. The evidence supports selected integration behavior, not universal safety, production benefit, statistical repeatability, or a comparative performance advantage. Never pool deterministic scenarios, independent component tests, historical model runs and R20 into a single success rate.
