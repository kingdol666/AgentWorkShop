\title{AgentWorkShop: A Governed Supervisory Execution Layer for Industrial Agent Teams}

\author{Anonymous Authors}
\markboth{IEEE Transactions on Industrial Informatics, Submitted Manuscript}{AgentWorkShop: A Governed Supervisory Execution Layer}

\maketitle

\begin{abstract}
Large language model (LLM) agents increasingly generate industrial control
changes, yet the surroundings of each proposal---who may write which
parameter, which limits bind for the current product and recipe, whether a
human approved, whether the device accepted, and whether the
process improved---are rebuilt per deployment inside application code. This
paper presents AgentWorkShop, a governed supervisory execution layer that
turns those concerns into one path for agent teams: each intervention is one
governed transaction whose admission, approval, actuation, graded write
acknowledgment, three-way setpoint consistency, verdict, and compensation
remain separately inspectable evidence states. Team identities reach semantic
data-acquisition (DAQ) and write-control (DCW) nodes through explicit
capabilities under a fail-safe line master switch; protocol drivers,
versioned production objects, plugin points, and a typed SDK form the
integration surface, with process models, objectives, and policies
external. The evaluation exercises this path through protocol-closure
and mechanism-ablation drills, agent-team missions, a deterministic controller
loop, four concurrent process missions, and a deployment-scale regression
campaign on one live multi-tenant instance (many provisioned lines and
channels on a single host). Every dispatched setpoint closes with a graded
acknowledgment and---where the endpoint supports readback---a three-way
consistency check across the recipe, the device readback, and a mirror sample
drawn over the acquisition path; pacing windows remain in force under
automation, and each scenario's optimization trajectory is archived with
per-step attribution. The result is an inspectable, simulation-tier
verification of the governance mechanisms themselves, not an
optimization-benefit claim.
\end{abstract}
