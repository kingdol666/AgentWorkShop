\title{Governed Setpoint Writing for Industrial Agents: A Configuration-Driven Runtime and Simulated Evaluation}

\author{}
\markboth{IEEE Transactions on Industrial Informatics, Submitted Manuscript}{Governed Setpoint Writing}

\maketitle

\begin{abstract}
Industrial agents can propose process changes, but each write must remain tied to the active production context, intended control point, and current limits. This paper presents a configuration-driven runtime that binds line, product, recipe, and run context to direction-specific signal mappings and routes task-mediated and direct calls through shared dispatch with route-specific revalidation and common write guards. Command outcomes and optional device readbacks are stored separately from later process observations. Across four simulated scenes, 220/220 admissible mapping probes were accepted, 219/219 collected structural-range probes were rejected, and 216/216 available simulated readbacks matched. In a mock-driver ablation, the enabled process-window guard stopped all six targeted violations before dispatch; removing it allowed all six to reach the driver. A separate single-run PLC-based simulated-twin pilot recorded a matching setpoint readback and a later process observation of 32.224~g within a 32.00--32.30~g band. In a three-scene comparison, 15/15 scripted endpoints and 0/15 no-write endpoints were in band; the scripted endpoints followed scenario-specific routines, whereas no-write used a fixed 60-s endpoint. This comparison cannot estimate efficacy. The live-Agent pilot issued no governed writes. The evidence supports selected simulator and mock-driver paths, not process-control efficacy or physical-plant safety.
\end{abstract}
