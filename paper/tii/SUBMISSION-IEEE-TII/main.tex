\title{Governed Setpoint Writing for Industrial Agents: A Configuration-Driven Runtime and Simulated Evaluation}

\author{}
\markboth{IEEE Transactions on Industrial Informatics, Submitted Manuscript}{Governed Setpoint Writing}

\maketitle

\begin{abstract}
An industrial agent can propose a setpoint change, but executing it requires the runtime to preserve production context, signal meaning, write authority, and process limits. We address this integration problem with a configuration-driven runtime that binds production context and named signals to operations and registered protocol drivers, and routes agent-proposed and direct calls through a shared dispatcher. Write handlers resolve live context, apply authorization and configured limits, and pass approved requests through a common guard before driver dispatch. Command receipts, actuator readbacks, and later process observations are recorded separately. In benchmark-mode simulated production scenes, probes checked selected node-to-driver mappings: all 220 admissible requests were accepted, 219 collected structural-range requests were rejected, and 216 available readbacks matched. A scripted mission reached its target band in all 15 seed--scene runs, whereas 0/15 no-write endpoints were in the band; because exposure time and mission logic differed, this is a descriptive demonstration, not a control-performance comparison. Removing the process-window guard allowed all six targeted violations to reach a mock driver, while structural checks remained active. A live-agent pilot issued no governed writes. The results support the tested configuration and guard paths in simulation. The architecture provides a configuration boundary for scene-specific operations, but the experiments do not establish live-agent performance, human-approval effects, or physical-plant safety.
\end{abstract}
