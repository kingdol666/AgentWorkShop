\section{Introduction}
\IEEEPARstart{L}{arge} language model (LLM) agents are being applied to
industrial control, factory skills, shop-floor coordination, and production
scheduling \cite{huang2026made,koehle2026llmdriven,lim2025llmenabled,zhao2026shopfloor,waseem2026pretrained}.
These studies show that agent reasoning can be connected to plant-facing
tasks, but deploying another process or line also changes signal maps,
protocols, operating objectives, and production context. A reusable
industrial-agent system must make those changes configurable while keeping
collaboration, plant integration, and operational workflows coherent.

Injection molding illustrates this systems problem. A team member may use
recent measurements and prior process knowledge to diagnose insufficient
packing and propose higher holding pressure. The framework must locate the
active product, recipe, and run; map the semantic quantity to a device
interface; apply the operation's configured checks; and return both
endpoint evidence and subsequent quality observations. The same team and
operational services should remain usable when another process changes the
signal map, protocol, or target criteria. A proposal, a confirmed setting,
and an observed process result therefore need distinct representations,
linked to the same production context.

The research question is how an extensible industrial-agent framework can
connect replaceable collaboration and strategy components to production
context and heterogeneous industrial I/O, while retaining route-appropriate
evidence from candidate action through process observation. AgentWorkShop
addresses this question through four cooperating design areas: channels,
teams, tasks, and shared memory host replaceable strategy adapters;
analysis, retrieval, dataset, and model services inform proposals; a
line--product--recipe--run model scopes work; and semantic acquisition and
write-control nodes bridge process quantities to protocol drivers.
Operational profiles and capabilities determine which workflow a channel
can invoke. Bounded node exploration and recipe operation then preserve
their distinct dispatch, observation, and retention lifecycles. Typed SDK,
REST, MCP, agent-to-agent, CLI, and console interfaces expose extension and
integration points.

This paper makes three contributions:
\begin{enumerate}
\item It presents a modular framework architecture that joins agent
collaboration and replaceable decision services with production objects,
semantic industrial I/O, and external extension interfaces.
\item It describes a configuration-based integration model in which
process-specific signal maps, protocol bindings, objectives, and guards
reuse shared orchestration and operational services, while node exploration
and recipe workflows retain route-specific evidence.
\item It evaluates protocol mappings, strategy substitutions, four
simulator-based process configurations, deployment-suite behavior, and a
recipe-path case. These experiments provide implementation evidence for the
exercised configurations; they do not estimate physical transfer or
comparative control benefit.
\end{enumerate}
The remainder presents related industrial-agent and integration work,
details the AgentWorkShop architecture and operational workflows, evaluates
the implemented routes, and discusses evidence scope and limitations.
