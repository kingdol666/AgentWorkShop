\section{Introduction}
\IEEEPARstart{I}{ndustrial} production systems expose measurements and control
points through devices and protocols configured for each production scene.
Before an agent request can reach a controller, the platform must resolve the
active line, product, recipe, and run; map the requested variable to the
intended control node; and apply the limits for that process. It must also
keep an accepted command separate from the later process observation. In the
cast-film configuration studied here, an MQTT endpoint carries a line-speed
setpoint and film-thickness samples. The shared endpoint does not make the
sample a readback of the setpoint or establish that the write caused a process
response.

Industrial-agent research addresses process supervision, control generation,
service selection, and human-guided automation
\cite{xia2025control,huang2026made,koehle2026llmdriven,biskupovic2025supervision,
liu2026agents4plc,wu2025instructmpc,lim2025llmenabled,zhao2026shopfloor,
hofmann2025nlc}. Other work connects agents with digital twins, manufacturing
skills, and shop-floor services
\cite{xia2025architecture,silva2025mcpmanufacturing,
koehle2025semanticrecipes,graul2026aas,schall2026safe,lin2026agentic}.
Industrial-informatics architectures have also formalized trust boundaries for
digital-twin control, functional blocks for industrial IoT networks, and
security services at the fog layer
\cite{gehrmann2020dtiacs,mahmood2023functional,sengupta2021securefog}.
Together, these studies address agent reasoning, asset grounding, industrial
communication, and guarded execution. The system-integration problem examined
here is how to connect agent runtimes to scene-specific signal and protocol
maps while applying the same operation checks to task-mediated and direct
calls.

We implement a configuration-driven architecture for this integration path.
Each scene binds its production context to semantic acquisition and
write-control nodes, protocol drivers, objectives, and engineering limits.
Harness adapters expose agent turns through a common operation interface.
Task-mediated and direct calls enter the same dispatcher; route handlers
resolve current context and apply route-specific limits and approval
requirements. Service-owned records distinguish command receipts from later
process measurements. The work contributes an integration architecture and
its implementation, rather than a new control law or agent algorithm.

The paper makes two contributions:
\begin{enumerate}
  \item A scene-configuration model that binds line--product--recipe--run
  context to semantic acquisition and write-control nodes, protocol drivers,
  process objectives, and engineering limits behind a common operation
  interface.
  \item A task-to-device runtime that separates harness execution from
  scene-specific I/O and routes task and direct calls through shared
  authorization checks. Route handlers enforce configured limits and
  approval requirements, while service-owned records preserve the distinction
  between command receipts and process observations.
\end{enumerate}

Section~II reviews related work. Sections~III and IV describe the architecture
and its execution and governance paths. Section~V reports workflow coverage,
protocol acquisition and guarded operations, simulator objective cases, and a
scripted BOPET task. Sections~VI and VII interpret the results and state the
scope of the evidence.
