\section{Introduction}
\IEEEPARstart{I}{ndustrial} optimization often occurs above the regulatory
control layer. Engineers adjust recipes, schedules, and setpoints to meet
quality, throughput, energy, or discharge objectives while PLCs and local
controllers retain fast regulation. The supervisory decision is only one part
of the intervention. A usable execution path must also establish which deployed
actor may change which parameter, which limits are active for the current
product and run, whether the device accepted the command, and whether the
process subsequently improved.

These concerns recur across plants whose physics and objectives differ:
injection molding couples part weight to pressure, time, and temperature;
wastewater treatment (WWTP) balances effluent constraints against aeration and dosing cost; annealing trades material properties against line speed; and BOPET (biaxially oriented polyester) production coordinates multiple stretching sections. All of them need an
auditable bridge from a team-level task to heterogeneous acquisition and
control nodes.

Large language model (LLM) agents are being studied for industrial diagnosis,
engineering assistance, and PLC-program generation
\cite{raza2025industrial,sabetta2025assistant,liu2026agents4plc,fakih2024llm4plc},
including simulated controller and machine interaction
\cite{vyas2026ftc,hofmann2025nlc}. Yet orchestration frameworks and protocol connectivity do not by themselves answer who is authorized, which production limits apply, or how a write is linked to later evidence (Section~\ref{sec:related}). Moreover, a task state such as
\texttt{COMPLETED} can coexist with a missed process objective.

\system{} addresses this execution gap through member--node bindings and shared
line, product, recipe, and run context. Nodes expose engineering quantities
rather than register addresses; bindings scope sanctioned tools; and
intervention records retain the proposal, execution result, observation, and
submitted judgment. Fig.~\ref{fig:intro} contrasts this organization with application-specific integration; fast regulation, certified protection, and the choice of optimization algorithm remain outside the framework.

The paper makes four contributions:
\begin{enumerate}
\item a \textbf{capability-based industrial execution architecture} that
connects agent-team identity, semantic data-acquisition (DAQ) and write-control (DCW) nodes, heterogeneous protocol drivers, and line--product--recipe--run context while keeping task membership
distinct from physical-write authority;
\item a \textbf{reusable integration boundary} consisting of self-describing
node and driver contracts, production objects, plugin extension points, and a
typed SDK. The evaluated reference adapter projects scenario blueprints into
these common services, while process models and policies remain external;
\item an \textbf{evidence-preserving governed intervention workflow} that
separates admission, optional approval, actuation, readback, process
observation, submitted judgment, compensation, and policy-driven backstop
actions; and
\item a \textbf{layered simulation-tier evaluation} spanning five protocol
stacks, a mechanism ablation, a deterministic controller, two AgentTeam
missions (one node and a nine-device line), and four process scenarios, with task state and objective attainment reported separately.
\end{enumerate}
The experiments use real software protocol stacks against author-implemented dynamic process simulators under deterministic scripted policies.
