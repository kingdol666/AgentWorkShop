\section{Related Work}
\label{sec:related}
Work relevant to this system spans industrial-agent supervision, agent-facing manufacturing interfaces, and operation governance. Supplementary Table S7-I compares representative systems; it does not rank their performance.

\subsection{Industrial Agents and Plant Integration}
Industrial agents have been used to supervise production services, generate control actions, program programmable logic controllers (PLCs), and coordinate manufacturing tasks. Biskupovic et al. study online service selection and reselection in service-oriented industrial cyber--physical systems \cite{biskupovic2025supervision}. Xia et al. connect language-model agents, digital twins, and automation systems \cite{xia2025architecture}; other work examines agent-generated control and PLC programs \cite{xia2025control,liu2026agents4plc,wu2025instructmpc}. Recent multi-agent studies evaluate module-level agents and skill execution in simulated manufacturing \cite{koehle2026llmdriven,zhao2026shopfloor}. These studies focus primarily on agent organization, control generation, or production coordination.

Agent-facing interfaces offer a second point of comparison. Vieira da Silva et al. examine MCP for exposing manufacturing capabilities as tools, and K{\"o}hle et al. compose semantic recipes from OPC UA skills \cite{silva2025mcpmanufacturing,koehle2025semanticrecipes}. Xavier et al. present IndustriConnect, an MCP adapter set for Modbus, MQTT/Sparkplug B, and OPC UA, tested with a mock-first workflow \cite{xavier2026industriConnect}. Liu et al. use agents and MCP to commission a cognitive digital twin by extracting specifications and binding live telemetry \cite{liu2026semanticcommissioning}. K{\"o}hle et al. combine module-specific agents, OPC UA skills, and MQTT coordination in nine simulated production challenges \cite{koehle2026llmdriven}. Together, these studies address tool exposure, protocol connectivity, semantic commissioning, and multi-agent execution. This paper focuses on the operation boundary that carries an active production tuple and named signal mappings through route-specific governance to a configured driver, while keeping command and process evidence distinct. The evaluation tests these paths; it is not a comparative performance study.

\subsection{Governed Agent Operations}
Safety and audit mechanisms have been integrated with agent execution in several forms. Graul et al. ground proposals in the Asset Administration Shell (AAS) and use signed approval, PLC-validated OPC UA Methods, and audit logging \cite{graul2026aas}. Schall separates large language model (LLM) proposals from verification grounded in piping and instrumentation diagrams (P\&IDs), supervisory control and data acquisition (SCADA), and standard operating procedures (SOPs), while Lin and Chen report a policy-governed sensor--manufacturing execution system (MES)--enterprise resource planning (ERP) digital thread \cite{schall2026safe,lin2026agentic}. Runtime enforcement and capability specification have also been proposed for agent tool use \cite{wang2025agentspec,debenedetti2025camel}, while industrial security and safety standards define separate zones, conduits, and safety-instrumented functions \cite{iec62443-3-3,iec61511}. The runtime studied here applies admission and approval between a named operation and its configured driver. PLCs, safety instrumented systems (SIS), and other plant-protection functions remain separate safeguards.

\subsection{Industrial Context and Operation Semantics}
MCP standardizes tool discovery and invocation, while operation-level scope, policy, grant, and resource-binding checks remain application concerns \cite{mcp2024}. ISA-88 and ISA-95 define recipe and production-operation concepts \cite{isa88_2010,isa95_2025}; run-to-run control relates process observations to later decisions \cite{moyne2000r2r}; human--automation research analyzes responsibility allocation \cite{parasuraman2000model}. These define the production entities and responsibilities the runtime must preserve. Section~\ref{sec:design} explains how they are carried into configured operations; Section~\ref{sec:eval} tests selected routes in simulation and against a mock driver.
