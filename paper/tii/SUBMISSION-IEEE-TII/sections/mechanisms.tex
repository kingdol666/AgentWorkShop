\section{Governed Execution Mechanisms}
\label{sec:mech}
A supervisory intervention must preserve distinctions that an agent tool call
usually collapses---permission to propose, admission of a value, driver
acceptance, device confirmation, process response, a caller's verdict, and
compensation---and \system{} exposes these as separate evidence states.
Three design commitments generate that separation: model output is an
untrusted proposal, never authority; evidence is graded by what is
observed, not claimed; and failure states surface for inspection rather
than being absorbed into a success flag.
A governed intervention is
one transaction in the audit-trail sense: every step
leaves its own evidence record, while execution and recovery are deliberately
not atomic with device state (Section~\ref{sec:limits}).
Six invariants organize the path---binding-resolved authority (never channel
membership or prompt content), Eq.~\eqref{eq:admission} admission
(Fig.~ef{fig:hitl}),
fail-closed approval waits on manual bindings, graded rather than
success-flag acknowledgment, checkable three-way consistency, and
separately admitted compensation---each specified below; every
agent-originated path to the plant passes through the same governed write.

\subsection{Task, Observation, and Admission}
\label{sec:objective}
The strategy receives a task and goal in
production context and decides what
to propose and when to stop; the platform governs semantic node
parameters---pressure, dosing rate, line speed, rail
width---in engineering units.

\looseness=-1 For an ordinary agent setpoint request on node $n$, the
admission interval is
\begin{equation}
\mathcal{I}_n(t)=\mathcal{H}_n\cap\mathcal{B}_n
                 \cap\mathcal{P}_n(t)\cap\mathcal{R}_n(t),
\label{eq:admission}
\end{equation}
where $\mathcal{H}_n$ is the mandatory hard engineering range (finite and
non-empty at node creation) and the remaining terms the baseline,
active-product, and active-recipe limits (together the soft window); a
missing optional limit
contributes no restriction, and $t$ is the
admission instant, re-resolved at execution. A configuration whose admitted
interval is empty rejects every write, naming the excluding layer on the
first attempt. The interval form is deliberate:
every bound is a declared, versioned object an audit can replay against
active product and recipe; rejection is decidable and layer-attributable
(Fig.~\ref{fig:hitl}a)---decidability, not a safety certificate.
It bounds one parameter at a time---joint windows live in scenario
guards---and bounds magnitude, not
intent: availability, binding state, and approval policy are checked
separately, and in-window but adverse sequences surface at verdict and
compensation (Section~\ref{sec:scenarios} reports two).

\subsection{Semantic Write, Pacing, and Source-Specific Routes}
\label{sec:nodeexec}
A semantic card exposes quantity, unit, precision, range, value, freshness,
and recipe context; the controller resolves binding and limits, the driver
serializes the command, and the acknowledgment grade closes the
command path, never the process-response path (Section~\ref{sec:ack}). Three pacing windows pace governed loops, never
the plant: online writes \emph{on a node}---agent- or human-origin---sit at
least 60\,s apart
with a hold window after success (HTTP~429 inside it); a per-recipe dispatch
interval anchored at the \emph{approval} instant is restart-persistent, so
alternating identities cannot reset it; and a 300\,s per-line trial cadence
damps same-line trials from any origin; recipe-dispatch and rollback
writes are exempt. \texttt{AW\_BENCH\_MODE=1} admits harness-declared arms that
relax the soft window or readback---never the hard range.

\looseness=-1 Four governed routes---agent tools, human-origin writes, recipe
dispatch, rollback compensation---reach
one admission and journaling entry point, the hard range included; recipe
dispatch adds run context---the line-scoped execution window, the reduced
ISA-88 batch/lot notion---validated at save time. Hold heartbeats (periodic
stored-setpoint re-dispatch) are the one non-governed re-dispatch:
off by default, stopped by line stop or driver change, and re-applying the
stored value without re-admission---plant-facing state maintenance, not an
agent path. Line start installs the active context before recipe parameters
dispatch individually; line stop clears it.

\subsection{Write Acknowledgment as Graded Evidence}
\label{sec:ack}
\looseness=-1 A driver-level success flag conflates two facts: the transport
accepted the command, and the device now holds the value. The platform grades
every governed write at two checkpoints. At \emph{acceptance}, the driver
records a provisional class: \emph{readback-verified} (its own post-command
read returns the commanded value within the node's configured write
tolerance), \emph{transport-acknowledged} (the transport accepted the command,
nothing device-side observed yet---a broker receipt or an MES business
acknowledgment), or \emph{unverified} (the transport failed). At
\emph{verification}, a post-write verifier re-reads the endpoint through the
node's read path (three attempts, 2\,s apart) and promotes
transport-acknowledged parameters whose read returns the commanded value; a
write that cannot be confirmed closes \emph{unverified}, and a command that
never completed acceptance closes \emph{failed}, overriding the provisional
unverified. The terminal grade is fixed when the write closes; the per-write
journal preserves the acceptance class and the terminal grade. We therefore
distinguish three evidence levels---readback-verified, transport-acknowledged,
and unverified---plus one terminal failure state, \emph{failed}. Batch receipts
carry a per-parameter terminal grade and a three-bucket summary
(verified/unverified/failed); the summary counts terminal outcomes, while
transport-acknowledged is a per-write terminal grade on acceptance-receipt
routes, not a batch bucket. The operations log records worst-state severity. The
falsifiable contrast: under a success-flag receipt rule---a transport
acknowledgment closes the report---the publish-only receipt of
Section~\ref{sec:hardening} (broker puback, \texttt{ok=true}, no read
channel) reports \emph{success}; the graded
rule reports it \emph{unverified}. Two boundary cases fix what the grades
mean: a MES write whose endpoint returns an explicit application-level
acceptance but exposes no readback mapping terminates
transport-acknowledged---an acceptance receipt, still short of device
confirmation---whereas a broker receipt alone terminates unverified.
Absence of evidence degrades the grade, never the report; the grade is
fixed when the write closes.

\looseness=-1 A transport-acknowledged write may still not have reached the
device; promotion through the verifier turns acceptance into
confirmation, and the three-way check of Section~\ref{sec:agentloop} re-reads
the value from the acquisition store. Recipe rollback restores a definition,
not physical PLC values, and a compensating write is graded by the same rule,
readback-verified where the endpoint supports readback and at best
transport-acknowledged where only an acceptance receipt exists. The grade
closes the command path only: readback-verified says the device holds the
value, not that the process responded as intended---that distinction belongs
to observation and verdict.

\subsection{Observation, Verdict, and Compensation}
\label{sec:agentloop}
\looseness=-1 An agent- or rollback-source write opens an optimization record;
the verdict tool
\texttt{dcw\_judge} records \texttt{keep}, \texttt{rollback}, or
\texttt{uncertain} plus a reason; the verdict, stored with the record it closes
and the window queried, performs no actuation and does not
independently validate the evidence, so a scripted keep can coexist with a
missed objective. Verdict integrity therefore rests on attribution,
journaling, and operator review---a kept-but-marked record stays visible
with its disagreement attached, and the operations log raises parameter
severity under alarm-rationalization practice---with the next
guard queued: an independent adjudication identity, or a platform-side
minimum re-check before a caller's \texttt{keep} may stand down the
backstop (Section~\ref{sec:limits}). Three-way
setpoint consistency is checked by the evaluation harness rather than the
platform: the harness compares the recipe
value, the device readback, and a mirror sample
drawn from the acquisition runtime's separate polling path and store, each leg
against a stated tolerance; the sampled legs meet at the plant endpoint, so a
fault fabricating the endpoint is their common failure mode, and disagreement is
reported with the run. Verdicts are attributable---actor and timestamp travel
with them.

\looseness=-1 Compensation is a new, separately admitted write that may fail or partially
complete; it is graded by the Section~\ref{sec:ack} rule, and a rollback
record settles to rolled back once the compensating write is accepted. If
the compensating write is itself refused by admission, the source record
closes \emph{as judged}, with the refusal appended to its verdict. These
separations keep command status, record status, and process recovery
independently inspectable.

\looseness=-1 The backstop is a record-integrity check for writes that no
verdict has closed---not an independent protection layer: it evaluates only
open records; a caller's \texttt{keep} closes and stands it down, while a
\texttt{rollback} verdict stands it down only once the compensating write
executes---availability is therefore contingent on
recorded verdicts and arriving observations. When collected samples of an open
record's node leave the recipe's monitoring window (a DAQ-side envelope
distinct from the admitting interval and from the mission's attainment
window), the platform issues a
system-attributed rollback verdict and restores the value preceding that
write (one step; the admitted baseline is not restored), graded as above.
The policy waits 120\,s, polls every 30\,s, and fires on three cumulative
out-of-window samples; non-returning samples count no breach, so an
acquisition outage leaves the record open and unalarmed. Recovery runs only
while fewer than two retained rollback records stand on the node; past that,
the backstop judges but defers actuation to the approval policy.

\subsection{Human Approval Boundary and the Line Master Switch}
\label{sec:hitl}
\looseness=-1 Manual bindings insert the timed approval wait before
an agent setpoint or
compensation request; automatic bindings omit the wait but keep the checks.
The pending request carries member, node, value, interval, expiry, the
proposer's reasoning, and per-parameter bases; Fig.~\ref{fig:hitl}b shows
the card's value row, reasoning line, and decision box---machine-checked
fields as structured data, the free text display-only and
non-authoritative. Because binding and admission are
re-checked at execution, approval reserves neither interval nor device state;
the approval dialog---itself an injection surface (Section~\ref{sec:limits})---
cannot promote a proposal past the checks; the comment returns verbatim
to the proposing member on refusal and travels with the receipt on
approval---feedback, not authority. The
wait fails closed by default (expiry 180\,s): an expired request
resolves as refusal and is recorded; duplicates are suppressed by holding
one pending request per member--node pair; and in \emph{hold} mode an
unanswerable request persists without expiry until a human answers.

\looseness=-1 Human authority is anchored one level above individual requests: each line
carries a control mode---the recipe-dispatch master switch---whose fail-safe default
is \emph{manual}. Under manual
mode, recipe-family operations (parameter update, dispatch, trial, and
rollback) from approval-free bindings on that line are intercepted and
presented for approval regardless of binding policy; direct node-tool
writes remain gated by their binding mode and the admission interval, not
by the line switch. Switching a line
to automatic requires an explicit admin-only user-side
confirmation; agent identities cannot touch the switch. The residual
agent-side path is delegation: a lead agent can grant held nodes to a
worker through an attributed lead-only tool; the grant's execution mode
is chosen at grant time rather than gated by the user-side confirmation,
is attributed to the granting agent, cannot exceed its own node
face, and is individually revocable (Section~\ref{sec:limits}).

\looseness=-1 The decision endpoint authenticates a user but does not enforce a line-scoped
approver role---the gap Section~\ref{sec:limits} carries---and reads,
verdict recording, and some configuration changes do
not use physical-write approval---workflow mediation, not segregation of
duties; a recipe switch between approval and execution re-admits the value
against the new window.
The engine is replaceable, not a control primitive---scenario code declares
and configures but never executes plant I/O, and the platform never infers a
process objective.
