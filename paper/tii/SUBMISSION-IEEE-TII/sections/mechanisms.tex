\section{Governed Execution Mechanisms}
\label{sec:mech}
A supervisory intervention must preserve distinctions that an agent tool call
usually collapses---permission to propose, admission of a value, driver
acceptance, device confirmation, process response, a caller's verdict, and
compensation---and \system{} exposes these as separate evidence states.
Three design commitments generate that separation: model output is treated
as an untrusted proposal, never as authority; evidence is graded by what is
observed rather than by what was claimed; and failure states are surfaced
for inspection rather than absorbed into a success flag.
Fig.~\ref{fig:runtime} shows the implemented agent-team
runtime that carries these steps; the governance and write stages drawn in
the figure are deterministic platform logic---no model output can admit,
approve, or confirm a write (Gate~1: admission interlock; Gate~2: approval wait). A governed intervention is
one transaction in the audit-trail sense: every step
leaves its own evidence record, while execution and recovery are deliberately
not atomic with device state (Section~\ref{sec:limits}).
Six invariants organize the path: authority resolves from the member--node
binding, never from channel membership or prompt content; the proposal must
lie in the Eq.~\eqref{eq:admission} interval; a manual binding inserts a
timed, fail-closed approval wait; the write leaves a graded
acknowledgment, not a success flag; three-way
setpoint consistency can be checked before any verdict; and compensation is a
separately admitted write referencing the record it reverses. Every
agent-originated path that \system{} exposes to the plant passes through the same governed write.

\subsection{Task, Observation, and Admission}
\label{sec:objective}
The strategy receives a task and goal in production context and decides what
to propose and when to stop; the platform governs execution over semantic node
parameters---pressure, dosing rate, line speed, rail
width---in engineering units.

\looseness=-1 For an ordinary agent setpoint request on node $n$, the
admission interval is
\begin{equation}
\mathcal{I}_n(t)=\mathcal{H}_n\cap\mathcal{B}_n
                 \cap\mathcal{P}_n(t)\cap\mathcal{R}_n(t),
\label{eq:admission}
\end{equation}
where $\mathcal{H}_n$ is the mandatory hard engineering range (finite and
non-empty at node creation) and the remaining terms the baseline,
active-product, and active-recipe limits; a missing optional limit
contributes no restriction, so the interval is always defined, and $t$ is the
admission instant, re-resolved at execution. Should a configuration empty the
intersection, every write is rejected with the excluding layer named, so the
misconfiguration surfaces at the first write. The interval form is
deliberate: every bound is a declared, versioned object that an audit can
replay against the active product and recipe, and rejection is decidable and layer-attributable, where a learned
feasibility model offers neither
(Fig.~\ref{fig:hitl}a). The claim is decidability and replayability, not learned-model safety.
It bounds one parameter at a time; joint,
cross-variable windows live in scenario guards. It is not a
physical safety certificate, and bounds magnitude, not
intent: availability, binding state, and approval policy are checked
separately, and in-window but adverse sequences surface at judgment and
compensation (Section~\ref{sec:scenarios} reports two).

\subsection{Semantic Write, Pacing, and Source-Specific Routes}
\label{sec:nodeexec}
A semantic card exposes quantity, unit, precision, range, value, freshness,
and recipe context; the controller resolves binding and limits, the driver
serializes the command, and the acknowledgment grade---not driver success
alone---closes the command path (Section~\ref{sec:ack}), never the
process-response path.

\looseness=-1 Two write-spacing windows pace governed loops, never the
plant. Online writes---agent- or human-origin---sit at least 60\,s apart, and
a successful one installs a hold window: a further request inside it
receives HTTP~429 \texttt{WRITE\_FREQUENT}. Recipe dispatch adds a
per-recipe interval anchored at the \emph{approval} instant of the preceding
dispatch---pending, refused, or expired requests do not start the
clock---keyed by recipe identity and restart-persistent, so alternating
agent identities cannot reset it; a coarser per-line trial cadence (300\,s
default) damps same-line trials from any origin. The hold installs only
after driver success; recipe-dispatch and rollback writes are exempt.
\texttt{AW\_BENCH\_MODE=1} admits harness-declared arms that relax the soft
window or the readback check---never the hard range.

\looseness=-1 Four governed routes---agent tools, human-origin writes, recipe dispatch, and
rollback compensation---reach the same driver through one admission and
journaling entry point, the hard range included; recipe dispatch adds run
context---the line-scoped execution window that gates dispatch, the reduced
ISA-88 batch/lot notion---validated against the recipe window at save time. Hold heartbeats---periodic
re-dispatch of the stored setpoint---are the one non-governed re-dispatch:
off by default, stopped by line stop, node disable, or driver change, and
re-applying the stored value without re-admission. The stored value changes
only through the governed path, so a narrowed window can leave a heartbeat
reasserting a previously admitted value---plant-facing state maintenance,
not an agent path.
Line start installs active context
before recipe parameters dispatch individually, and line stop clears context
and closes retained open records; these multi-step operations are not atomic
with device state.

\subsection{Write Acknowledgment as Three-Level Evidence}
\label{sec:ack}
A driver-level success flag conflates two facts: the transport
accepted the command, and the device now holds the value. \system{} grades
every governed write into one of three acknowledgment levels:
\emph{readback-verified} when an independent read---one issued outside the
write path---returns the commanded value within the node's configured write
tolerance;
\emph{transport-acknowledged} when the transport
accepted the command on an endpoint with no usable readback;
\emph{unverified} when the transport failed or when post-write verification
could not confirm the value. The grading rule is falsifiable. Under a
success-flag receipt rule---the pattern in which a transport acknowledgment
closes the report---the publish-only receipt archived in
Section~\ref{sec:hardening} (broker \texttt{puback}, \texttt{ok=true}, no
read channel, three verification attempts) reports \emph{success}; the
graded rule reports it \emph{unverified}. That is what fail-honest means:
absence of evidence degrades the
grade, never the report---a write without confirmation is surfaced as
unverified, with the transport error attached, rather than dropped from the
receipt; the grade
is fixed when the write closes, so later confirmation belongs to the record
and to the three-way check, not retroactively to the receipt.

A transport-acknowledged write may still not have reached the device, so a
post-write verifier re-reads the endpoint (three attempts, 2\,s apart) and
promotes the grade when a read confirms the value. Batch receipts carry a
per-parameter grade plus a summary; the write journal stores the per-write
grade, and the operations log records the judgment at worst-state
severity. Recipe rollback restores a definition,
not physical PLC values, and a compensating write is itself graded by the same
three levels. The grade closes the command path only: readback-verified says the device
holds the value, not that the process responded as intended---that
distinction belongs to observation and verdict.

\subsection{Observation, Judgment, and Compensation}
\label{sec:agentloop}
\looseness=-1 An accepted write opens an optimization record; the verdict tool
\texttt{dcw\_judge} records \texttt{keep}, \texttt{rollback}, or
\texttt{uncertain} plus a reason; the verdict, stored with the record it closes
and the response window actually queried, performs no actuation and does not
independently validate the evidence, so a scripted keep can coexist with a
missed objective---verdict integrity rests on attribution, journaling, and
operator review: a kept-but-marked record stays visible with its
disagreement attached, and the operations log raises parameter severity
under alarm-rationalization practice (Section~\ref{sec:limits}). A three-way
consistency test compares the recipe
value, the device readback, and a mirror sample
drawn from the acquisition runtime's separate polling path and store, each leg
against a stated tolerance; the sampled legs meet at the plant endpoint, so a
fault fabricating the endpoint is a common-mode boundary.
Disagreement marks the record even when every grade verifies. Verdicts are attributable---actor and timestamp travel
with them; corrections amend the stored reason visibly, and compensation
opens a new record referencing the one it reverses.

Compensation is a new, separately admitted write that may fail or partially
complete; its dispatch is graded by the Section~\ref{sec:ack} levels, and a
rollback record settles to
rolled back once the compensating write is accepted---readback-verified where
the endpoint supports readback, transport-acknowledged otherwise. If the
compensating write is itself refused by admission (a baseline can drift out
of a narrowed window), the source record closes \emph{as
judged}, not rolled back, with the refusal appended to its verdict and
surfaced in the operations log. These
separations keep command status, record status, and process recovery
independently inspectable.

\looseness=-1 The backstop is a record-integrity check for writes that no
verdict has closed---not an independent protection layer: it evaluates only
open records, and a caller's keep or rollback closes the record and stands it
down, so its availability is contingent on a verdict being recorded and on
observations continuing to arrive. When the
recorded value of an open record leaves the admitting recipe window, the
platform issues a system-attributed rollback verdict
and restores the value preceding that write (one step; the admitted
baseline is not restored), the
compensating write graded as above. The stored policy waits at least
120\,s, checks at most every 30\,s, and triggers once three out-of-window
points or averages accumulate in the observation window---cumulatively, not
necessarily consecutively. Points that do not return contribute no breach, so
an acquisition outage leaves the record open, monitored but untriggered, a
silence the platform does not currently alarm on. Recovery executes only
while fewer than two
retained rollback records stand on the node---past that, the backstop
still judges and records but defers actuation to the approval policy that
governed the write, bounding any rollback loop at the two-record cap.

\subsection{Human Approval Boundary and the Line Master Switch}
\label{sec:hitl}
\looseness=-1 Manual bindings insert the timed approval wait before
an agent setpoint or
compensation request; automatic bindings omit the wait but keep the checks.
The pending request shows member, node, value, interval, and expiry---in the
deployed benchmark, plus the proposer's reasoning and per-parameter basis
(Fig.~\ref{fig:hitl}b): machine-checked fields are structured data, the
free-text reasoning display-only and non-authoritative. Because binding and admission are
re-checked at execution, approval reserves neither interval nor device state;
the approval dialog---itself an injection surface (Section~\ref{sec:limits})---
cannot promote a proposal past the checks; the comment returns verbatim
to the proposing member on refusal and travels with the receipt on
approval---feedback, not authority. The
wait fails closed by default (expiry 180\,s, configurable): an expired request
resolves as refusal, does not actuate, and is recorded with the expiry;
duplicates are suppressed by holding at most one pending request per
member--node pair regardless of the proposed value, and card creation
inherits the write pacing windows, so the pending set is paced like the
writes themselves. In \emph{hold} mode an unanswerable request persists---no expiry, periodic
reminders to the line's operate-scoped users---until a human answers; a
repeat governed request for the held node is refused as a duplicate, and
other nodes proceed under their own policy.

Human authority is anchored one level above individual requests: each line
carries a control mode---the line master switch---whose fail-safe default
is \emph{manual}. Under manual
mode, writes from approval-free bindings on that line are intercepted and
presented for approval regardless of binding policy, and switching a line
to automatic requires an explicit, admin-only user-side
confirmation---agent identities hold no
binding-administration capability, so an agent cannot reclassify its own
writes as approval-free.

The decision endpoint authenticates a user but does not enforce a line-scoped
approver role, and reads, verdict recording, and some configuration changes do
not use physical-write approval---workflow mediation, not segregation of
duties; a recipe switch between approval and execution re-admits the value
against the new window (Section~\ref{sec:limits}).
The strategy engine is replaceable rather than trusted as a control
primitive: the stable plane keeps bindings, semantic I/O, evidence, approval,
compensation, and backstop handling, while scenario code declares and
configures---never executing plant I/O---and the platform never infers a
process objective.
