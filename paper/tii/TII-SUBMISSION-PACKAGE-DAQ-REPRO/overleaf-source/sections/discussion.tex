\section{Discussion}
\label{sec:discussion}
The intended agent-mediated sequence---acquisition, objective-conditioned analysis, typed intent, governed dispatch, and reassessment of returned evidence---becomes explicit in the runtime (Section~\ref{sec:closed-loop-operation}). The selected fixed-horizon batch had lower retained-window error under the deterministic policy than under no-write in all nine valid blocks; Section~\ref{sec:eval} details the comparison's exploratory limits.

The runtime separates acquisition from write authorization: scene configuration maps observations and setpoints to distinct protocol addresses, and the dispatcher applies the checks required by each write route. The reply to a control tool, a device readback, and a later process observation answer different questions. A matched readback verifies a simulated setpoint, not its effect on the process. The tests cover selected paths; neither the mapping matrix nor the guard fixtures establish equipment safety.

Fig.~\ref{fig:optimization-trajectory} presents the recorded injection mass traces and setpoint requests alongside the selected IAE contrasts; iteration-level timing and per-request server records are unavailable, so causal effects are not established. The mapping and guard tests support only the exercised branches; their oracles share configuration with the tested limits, and simulator readback is not physical actuation evidence. The LLM-driven episodes returned acknowledged updates but ended below target, and without the server journal cannot establish a complete agent-to-device write chain.

For the historical trials, the complete service and configuration snapshot was not retained. The archived samples support recalculating IAE but not recreating the deployed runtime. A confirmatory comparison would require prespecified inclusion rules, verified resets, a common sampling protocol, and a named controller baseline. Evaluating autonomous agent control would also require repeated tasks with correlated observations, decisions, and device records. Human approval effects and physical safety require separate studies.

Two extensions follow, and both remain future work. The first is autonomous closed-loop optimization through agent-architecture orchestration: a lead agent decomposes an objective, dispatches governed exploration or recipe steps, and reassesses returned evidence until a stopping rule is met---with every write still passing the same dispatch, approval, and revalidation checks. The second is process-experience memory reuse: validated scene-specific experience---operating context, applied intents, and observed outcomes---would accumulate and condition later proposals. Neither extension alters the boundary invariants. Both would inform proposals and sequencing only, granting no write authority.

\section{Conclusion}
\label{sec:conclusion}
This work presents a configuration-driven runtime that maps acquisition and control signals separately and checks a typed write intent before dispatch. The direct probes and guard fixtures support the exercised application-level paths. The historical two-turn trace adds an agent-reported acquisition summary and a journal-linked simulator write with matching readback. The fresh cast-film attempt reached the device-driver read but did not verify Agent retrieval or a trial write. The E6 scripted comparison remains exploratory, and the three E7 episodes ended below target. These results do not establish autonomous optimization, a causal process effect, or safety on physical equipment.
