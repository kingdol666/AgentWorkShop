# Anonymous experimental evidence supplement

This delivered copy accompanies the October 26 IEEE TII manuscript. It extends the October 20 historical archive with R11/R12 boundary records, the current-version Q7 integration run (R13), its exploratory signal-pair pilot (R14), an earlier infrastructure-blocked attempt (R15), the deterministic registered-harness fixture (R16), the current model-driven run (R20), and the separate current-version deterministic fixture verification (R21), direct REST operation run (R22), and registered Pi local-fixture task run (R23). The source October 20 ZIP remains unchanged.

Use `CLAIM-MAP.json` to locate manuscript claims by evidence unit and artifact path. `MANIFEST.json` records source and delivered hashes, byte counts, and copy transformations. `FILES.json` hashes the delivered entries except itself. `VALIDATION.json`, `DUPLICATES.json`, and `MISSING-EVIDENCE.json` retain their original archive scope. The October 25 and October 26 extension records document their added artifacts and copy transformations.

R1--R10 are historical evidence. R11/R12 preserve failed boundary checks. R13 ran a local v0.8.0 application-level integration script against two isolated repository simulators: protocol reads, bounded writes, readback, and dataset lineage passed, but both model candidates failed eligibility or validation gates; no optimization recommendation or dispatch was produced. R14 records the exploratory signal-pair pilot that preceded R13 and is not pooled with it. R15 stopped before line creation or process sampling. R16 records a deterministic fixture diagnostic and is not pooled with the current model-driven run. R20 records six sequential registered-agent task executions, three per scene, using one simulator instance per scene. Each receives synthetic approval, one route-specific recipe-trial record, and a 1/1 verified readback. After verifying the route ACK and returned trial result, the runner waits 20 s, probes and ingests one sample, queries it by active run ID, and then checks task state. No task-completion timestamp was retained, so task-completion-to-sample latency is unrecorded. The generated `revision-2026-10-25/R20/R20-TRACE-MATRIX.csv` maps each execution key to its task, run, approval, trial, receipt checks, sample run IDs, value, and post-query task state; `R20/evidence.json`, logs, runner, and source snapshot retain the underlying records. The sample is ingested through an isolated SQLite fallback; all six remain outside target bands. This does not establish independent replication, convergence, quality improvement, normal online DAQ performance, or portability. All plant tests use software simulators; no physical-plant transfer, successful current-version optimization, or comparative control benefit is established. R20 records source hashes and working-tree state; the reported run is not an exact historical commit replay. R13's report did not pin the application, test-script, simulator, or installed dependency identities at execution; R13-PROVENANCE.json gives retrospective source context and states this limitation. R21 separately reruns the deterministic local OMP-RPC fixture on v0.8.0 in two scenes without an LLM decision. Each task context produced one approved recipe trial, verified receipt/readback, and active-run-tagged sample; 31 runner assertions and 25 isolation assertions passed, including cleanup. This is a deterministic software path check, not a live-agent replication, task-completion result, process-performance test, or second R20 repetition. See `revision-2026-10-25/R21/R21-TRACE-MATRIX.csv` and its evidence and logs. R22 separately tests the direct REST tool endpoint, one bounded call per scene, without a task, harness transport, or LLM. Each synthetic approval produced a 1/1 verified receipt/readback and one active-run-tagged snapshot; both snapshots were outside target. All 19 checks passed. R22 broadens invocation-route coverage, not process response; its run records and runner are under R22/. R23 exercises the registered Pi CLI adapter with a deterministic loopback fixture, one task per scene, no external model decision, synthetic approval, verified receipt/readback, and a run-tagged sample after 20 s. Both tasks completed and both samples were below target; 37 application and 28 isolation checks passed. The R23 trace matrix joins task, approval, trial, active run, and sample; this verifies the tested route only, not Pi model quality, general adapter interchangeability, or process response.

 R24 is a separate v0.8.3 working-tree replay of one documented C01 blueprint. Its source commit was not pinned. The isolated run used a local Modbus/TCP PLC twin, MES REST simulator, and dedicated online MQTT/Timescale services; object storage was unavailable and image artifacts used local-disk fallback. Connectivity passed 3/3, line provisioning 20/20, channel construction 13/13, V1--V6 verification 23/23, and the onboarding smoke 11/11. A test-only automatic approval changed line speed from 37 to 39 m/min and the PLC twin confirmed the write. This is one simulated configuration instance, not evidence of arbitrary portability, profile reuse, repeatability, physical transfer, human-review performance, or process quality. The delivered health record replaces the product label with a generic label; the original and delivered hashes are recorded in MANIFEST.json.
