\section{Discussion}
\label{sec:discussion}
The runtime makes the intended agent-mediated sequence---acquisition, objective-conditioned analysis, typed intent, governed dispatch, and reassessment against returned evidence (Section~\ref{sec:closed-loop-operation})---explicit. The selected nominal fixed-horizon batch had lower retained-window accumulated error with the deterministic policy than with no-write in all nine selected valid blocks; the exploratory limits of this comparison are detailed in Section~\ref{sec:eval}.

The evaluated runtime supports a concrete functional envelope: scene configuration binds production context to direction-specific acquisition and control mappings and registered protocol drivers; task-mediated and direct calls converge on one shared dispatcher; typed control intents pass execution-mode, authorization, write-limit, conditional-approval, and route-specific revalidation checks, with step, interval, and hold-window guards outside benchmark mode; and governed exploration and recipe-trial routes return command outcomes, readbacks, and later DAQ observations as separate, verification-graded records. Section~\ref{sec:eval} exercised this envelope across four simulated scenes and five protocols. The loop itself, however, has not been executed end-to-end by an autonomous agent: iteration requires a subsequent agent decision, and all three language-model-driven episodes were canceled below target. The runtime therefore realizes a governed execution boundary; the closed-loop control mechanism---iterative acquisition, adjustment, and reassessment---is not yet realized in operation.

Fig.~\ref{fig:optimization-trajectory} presents the recorded injection mass traces and setpoint requests alongside the selected IAE contrasts; iteration-level timing and per-request server records are unavailable, so causal effects are not established. The mapping and guard tests support only the exercised branches; their oracles share configuration with the tested limits, and simulator readback is not physical actuation evidence. The LLM-driven episodes returned acknowledged updates but ended below target, and without the server journal cannot establish a complete agent-to-device write chain.

A complete immutable service and configuration snapshot was not retained; application checks complement PLC, safety-instrumented-system, and equipment protections. Further process validation requires a larger pre-specified study with verified reset states, common sampling and horizons, a named controller baseline, and complete trajectories; agent evaluation requires a fixed acquisition-and-control task, retained model and runtime versions, and correlated observation-to-intent-to-device records; human-approval effects and physical safety need separate studies.

Two extensions follow and remain future work. First, autonomous closed-loop optimization could be pursued through agent-architecture orchestration: a lead agent decomposes an objective, dispatches governed exploration or recipe steps to worker agents, and reassesses returned evidence until a stopping rule is met, with every write still passing the same dispatch, approval, and revalidation checks. Second, process-experience memory reuse could accumulate validated scene-specific experience---operating context, applied intents, and observed outcomes---to condition later proposals. Neither alters the boundary invariants: both would inform proposals and sequencing only, granting no write authority.

\section{Conclusion}
\label{sec:conclusion}
This work presents a configuration-driven runtime for agent-mediated online data acquisition and governed setpoint control. It binds production context and direction-specific acquisition and control signals, returns observations for objective-conditioned analysis, and carries a typed control intent through route-dependent checks before dispatch, keeping command outcomes, readbacks, and later observations distinct. Mapping and guard branches were exercised in simulated scenes and mock-driver fixtures; all nine valid fixed-horizon scene--seed pairs had lower retained-window IAE under the scripted policy than under no-write, subject to the unresolved batch-selection rule and absent controller baseline, and the three LLM-driven episodes were canceled below target without a complete server-side write record. The evidence establishes an application-level agent-to-operation integration boundary, not autonomous closed-loop control, general optimizer convergence, a complete agent-to-device trace, or physical-plant safety. Realizing autonomous closed-loop operation through agent-architecture orchestration, with reuse of accumulated process experience to condition later proposals, is future work that must remain inside this governed boundary.
