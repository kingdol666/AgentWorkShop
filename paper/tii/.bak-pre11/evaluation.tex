\section{Integrated Evaluation}
\label{sec:eval}

\subsection{Evidence Design and the Reference Run}
\label{sec:protocol}
\label{sec:static}
Four questions drive the evaluation. Can the platform commission heterogeneous
protocol stacks and acquire from them? Does the governed write path reject requests
that break engineering or recipe constraints without blocking legal ones? Can a
fixed controller close the acquisition--actuation loop on a process model? Can a
scripted team turn a production objective into governed actions that reach it?
Source
inspection, mock drivers, real protocol transports driving simulated plants, and
historical LLM campaigns stay apart; nothing here comes from physical hardware or
human operators, and no observed latency is an equivalence result.

Every measured result in this section comes from one reference archived run,
$B=\texttt{20260918043504-bdo}$: seed 42, commit \texttt{7d4bfc0}, harness hash
\texttt{00e7dc827f4a2cea}, Node v24.19.0 on Windows x64. It holds 75 checks that all
pass, with no warnings and no failures. The objective, control law, and probe
definitions are not in the archive; they are fixed properties of the harness source
named by that hash. The run therefore measures platform, protocol, governance,
controller, and team mechanisms: the agent-tool loops use the deterministic
\texttt{opencode} engine, and the LLM agent option is off. Three plants are exercised: a
cast-film physics model, a strategy-based film line, and a 49-signal biaxial (BOPET)
line.

The checks behind these numbers are the per-line integration checks \texttt{line-$n$-io} in phase P3 and \texttt{port-$n$-*} in phase P8. Each writable stack rejects four engineering-range and two recipe-window
violations, giving 24/24 rejections, and none of the four designated legal writes is blocked.
The probes are node-high plus 15\,\% of span, node-low minus 15\,\%,
$10^{6}$, $-50$, and the recipe window widened by 20\,\%, so the set shows rejection
of gross violations and nothing about where the true limit lies. With six samples,
and with the OPC UA readback contradicting ``exact'' on two earlier writes in the
same archive, the readback column is an illustration rather than a characterisation.
Modbus TCP carries the longest latency tail at 162.607\,ms while OPC UA and MQTT
respond inside 22\,ms, but these are observations under one host and one simulator,
not an equivalence conclusion. MQTT and HTTP publish or echo without returning a
measured value, so their accepted writes are unverified rather than process
confirmation.

The same run provisions the film-line scenario with three writable lines and two
satellite nodes. Its nine out-of-constraint probes, three node-range probes per writable line, are all rejected and its three legal writes accepted, with no code change. That set exercises no recipe-window branch. Both scenarios come from the same
simulator and the same five drivers, so this is configuration reuse within the
existing vocabulary, not portability to an independent plant.

Reverting a recipe creates a
new version rather than overwriting the old one; a known-good batch is retained; a
recorded rollback verdict leaves the register untouched until a separate rollback
call passes through the write path; and manual mode suspends an agent request until
the scripted approval releases it, measured at 16\,ms, which times the approval polling path rather than a human decision. The audit
surface holds 11 parameter-change anchors and returns 200-entry audit and
operations-log windows, so intent, approval, and execution are separately
inspectable, though the journal is not a signed ledger and protocol I/O is not
atomic with a concurrent recipe change.

A frozen four-arm ablation on the same API surface, archived separately in the repository, shows what the write path contributes. With the full path, all six attacks are rejected. With the batch-window interlock disabled, four are still rejected and the two recipe-window violations execute at the driver; disabling readback alone changes nothing in this arm. The engineering range is therefore structurally enforced and the batch-window check is the one that adds protection, while attribution records what happened without preventing it. The same archive carries boundary probes one tenth of a unit either side of the window edge, all of which are rejected with no false block in any arm. The ablation is a separate archive with its own fingerprint and is not part of the 75 checks of archive $B$. The process-parameter layer passes 4/4 checks: its semantic surface exposes no
register or driver-configuration field, writes are bounded by the intersection of
node, parameter, product, and recipe limits, out-of-product and out-of-baseline
values are rejected at their respective layers, the parameter reads back, and an
unbound agent is denied. Agents thus receive a process-facing interface that does
not disclose transport addresses; the layer was added late in development and is
absent from Section~\ref{sec:mech}.

\subsection{Fixed-Controller Closed-Loop Benchmark}
\label{sec:clbench}
The controller in this layer contains no LLM. It starts the cast-film twin at screw
speed $N=150$\,rpm, line speed $v=95$\,m/min, and zone setpoint $200\,^\circ$C, and
\emph{maximizes} the objective
\begin{equation}
J = 55\,J_\text{thick} + 25\,J_\text{quality} +
8\,J_\text{energy} + 7\,J_\text{throughput},
\label{eq:objective}
\end{equation}
subject to melt temperature in $[195,225]\,^\circ$C and pressure at most 22\,MPa.
Each term is a normalized score in $[0,1]$, so $J\in[0,95]$: thickness quality
saturates once $|h-50|\leq2\,\mu$m, and the other terms reward low defect rate, low
screw speed, and high line speed. The controller updates $N\leftarrow N(50/h)$ under
a 22-rpm step limit, holds line speed fixed, and corrects heating only when
temperature leaves $[196,224]\,^\circ$C. The objective, control law, and reference $J^{*}$ come from the harness and the separately maintained simulator, not from the run. Two features of that scoring bound the ratio. Its throughput and energy terms are evaluated from the setpoints the controller issued rather than from measured values, because the twin returns no independent reading for them; and the control law inverts the model's own relation $h\propto N/v$, so the plateau is structural. The suite's gate is $J/J^{*}\geq0.8$, so the reported value is not near a threshold.

The three seeds start at $J_0=70.115$, 68.792, and 70.248. All six governed writes
are accepted, none rejected, and the mean wall time is 36.193\,s per seed. The
archive reports an end-of-run score $J_{\rm end}=87.105$, 87.027, and 87.366,
defined as the mean of the last two evaluations, giving
$J_{\rm end}/J^{*}=0.969$, 0.968, and 0.972. The last measured evaluation is lower
in every seed, at 86.921, 86.609, and 86.975, or 0.967, 0.963, and 0.968. The
stopping rule requires two consecutive converged observations, and the first write
already brought thickness inside the $50\pm2\,\mu$m plateau, so the second write
follows from the rule and not from a further improvement: it raises defect rate from 0.38--0.53\,\% to 0.62--0.72\,\% and lowers the composite objective. Seed~44 shows the largest relative rise in defect rate. We therefore
quote $0.963$--$0.972$ across both conventions and do not describe the trajectory as
monotone. Final thicknesses are 49.883, 49.383, and 49.317\,$\mu$m.

Decomposing $J$ at the final point shows the residual gap. The reference and the
seeds both saturate the thickness term, so thickness contributes nothing to the
difference; at seed~42's final point the seeds give up about $1.8$ points on defect quality and $4.4$ on screw-speed energy, but gain about $3.2$ on line throughput, because the controller
holds line speed at 95\,m/min while the reference reaches $h=49.18\,\mu$m at
40\,m/min and 55\,rpm. The gap therefore reflects the controller's restricted action set, not a failure to reach thickness. The reference is the best value on a finite grid
whose resolution the archive does not record, so the ratios measure distance from
that grid, and the two-write count belongs to this stopping rule, not to the
controller.

\subsection{Scripted Team Missions}
\label{sec:agentloop}
Both missions are dispatched by \emph{scripted} channel members: the harness creates
the lead and the worker on its mock engine and the benchmark script issues every
tool call itself, so no language model decides a setpoint. The missions exercise the
path an agent would use, not agent performance. The first asks whether an objective
filed on the channel task board can travel through team delegation, a governed
write, and back to a closed task: bring a Modbus-TCP temperature node to
$204.704\pm0.75\,^\circ$C in at most three governed writes after reading recent
data. The lead dispatches the task, a bound worker performs a five-minute
\texttt{daq\_query}, and one \texttt{dcw\_control} request raises the setpoint from
200 to 204.704. The readback returns 204.700, an optimization record opens and is
judged \texttt{keep}, the journal attributes the write to the agent, and the parent
task reaches \texttt{COMPLETED}. All six mission checks pass, but the band is loose
relative to the write, since a request for 204.0 would also have passed: the path
closes, but the target was not hit precisely.

The second mission is the more demanding one. Fig.~\ref{fig:agentteam} maps it end
to end: the line, the team, the admission gate, the three recorded writes, and the
response they produced. The biaxial-film preset is provisioned as one full line with nine
devices, 30 writable setpoints, 19 configured acquisition nodes, and driver tests
passing on all nine; all nine came from the benchmark's own probe-and-provision
step, so this layer measures provisioning and governance, not commissioning a line
that already existed. The scripted team files a thickness objective of
$25.0\pm0.7\,\mu$m, accepted as $|h-25.0|\leq0.7\,\mu$m. The initial gauge reading,
taken through the real MQTT path, is 28.10\,$\mu$m, outside the window. The worker

two protocols and two engineering units. Every write cleared the gate shown in the figure (checks \texttt{biax-mission-multinode} and \texttt{biax-mission-attained}), was accepted by its driver, opened its own
optimization record, and was followed by a gauge re-read after a settling wait. Only
those parts are recorded: the archive stores no post-write readback value for these
three writes, so we claim none. The verdicts are not an independent finding either,
since the scripted caller issues \texttt{keep} unconditionally; the records show
that judgment is stored separately from execution and compensation, not that a judgment was earned. This attainment is one archived observation, and a later run of the same command did not reproduce it. The journal query for the cast-speed node returned the record with an agent source, which is the parameter-ledger surface of Section~\ref{sec:port}; the separate mission check that asserts journal attribution is the one recorded with an empty evidence array in Section~\ref{sec:repro}.

The final thickness is 25.68\,$\mu$m, satisfying $|h-25.0|=0.68\leq0.7\,\mu$m by
$0.02\,\mu$m on a short bucket mean, and the mission closes with 3 of its 6 allowed
writes used. Melt temperature stays near $291.5\,^\circ$C inside its
268--300\,$^\circ$C process window, an observation rather than an enforcement
result, since no disturbance tested that bound.

The mission is a scripted policy, not a search: each actuator carries a preset
proportional gain applied to the relative thickness error, and the actuator is chosen
by fixed rotation through the three knobs. The gains, $0.5$, $0.35$, and $0.3$, were
set deliberately low so that convergence takes three to four rounds and more than one
node is involved; both the shrinking response ($1.48$, $0.72$, and $0.22\,\mu$m) and
the three-write length follow from that configuration, not from emergence. What the
mission does show is operational: the binding model resolves a different node,
range, unit, and recipe window for each write, and the record structure keeps the
three writes separate while attributing them to one objective. It does not establish
autonomous strategy quality, cross-model generality, or physical-process
performance.

\subsection{Reproducibility, Recovery, and Threats to Validity}
\label{sec:e1a}
\label{sec:repro}
The backstop drill freezes a process variable outside its active window; the harness
injects the breach rather than a drifting plant producing it. The system identifies
an eligible open record, records a rollback judgment, and restores the recorded
baseline in 120.161\,s, a latency set by the backstop's own wait-then-recheck cadence
rather than by the plant. The drill shows one bounded recovery execution: it does
not exercise escalation at $K=2$, does not test detection of a slowly drifting
excursion or of a gap between batches, and sets no worst-case recovery deadline. The
same run stores five vector contour frames and five image frames, completes a
lead-to-worker dispatch, stores a duplicate memory refresh once, and enumerates 14 registered
harnesses, an inventory result that says nothing about control quality across those
engines.

Three failures observed outside archive $B$ bound the governance claim. During harness
development, a burst of writes across several protocols drove the simulated plant
into a collapsed state, with pump pressure, draw ratio, and thickness falling to
their limits, while every platform-side write stayed readback-consistent. A readback
therefore confirms that a driver delivered a value, not that the plant is in a sane
state. A film-break guard that reapplies the recipe baseline is present in the mission harness but is not represented in archive $B$, which never entered that branch. Three other archives did, one of them 26 minutes earlier at the same recorded commit, and in every case the re-application failed to restore thickness, leaving final readings of $0.04$, $-0.02$, and $-0.02\,\mu$m. The guard therefore aborts rather than recovers, and a negative thickness indicates that the plant model, not only the governance layer, bounds this result. Third, the audit path fails open: bookkeeping errors are caught without reversing an executed write,
so a physical change can occur without an attribution record, and the platform logs
the error without blocking the write or retrying the record. Attribution is
therefore a strong default, not a guarantee.

The command
(\texttt{node bench/pipeline.mjs --profile integrated --seed 42 --cl-seeds 3}),
seed, commit, and a hash over the nine checker sources let another operator rerun
the suite and compare judge-class outcomes against the same baseline. Four caveats
keep this short of full reproducibility. The hash covers checker sources in the
working tree, so it is sensitive to checkout line endings, and the plant simulator
is a separately versioned dependency whose revision is not in the fingerprint, so
the exact harness and plant behind these numbers cannot be reconstructed from the
archive alone. The biaxial journal-attribution check is recorded as passing with an
empty evidence array, so the run's own bookkeeping is not uniformly clean. And the
checks were written against this implementation, with $J^{*}$ drawn from the same
simulator whose score function the controller optimises, so the gate is a
development-time regression suite, not a benchmark with an external oracle. A fifth caveat concerns the mission layer. Its starting thickness is a simulator residue rather than a pinned initial condition, and later runs of the same command on the same host reached different outcomes: two archives sharing one harness hash and one seed, neither of them $B$, ended at $25.68\,\mu$m and at $-0.02\,\mu$m; in the second, both mission checks are recorded as warnings, no check failed, and the hard gate stayed green. The suite is therefore not deterministic at the mission layer, and the 75/75 gate describes archive $B$ rather than a property of the system. Verdicts and record states are deterministic within a run, protocol latencies are not, and the two should not be read as interchangeable. The evidence remains simulation-tier, and no
physical device, TEP or SWaT replay, human-operator workload study, or
external-framework comparison was run.

Historical real-LLM campaigns are exploratory evidence only. They use the same
governed interface but different scoring inputs and temporal windows, the legacy
script substituted missing observations, and the completion regex could match an
instruction template, so their scores are not aggregated with the results above.
Archive $B$ uses the scripted path so that model variability does not enter the
mechanism claims; where the platform's evaluation machinery proved weakest, in
observation quality, we say so in Section~\ref{sec:limits}.
